## 0. 已定决策

| 决策点 | 结论 | 说明 |
|---|---|---|
| **主视觉基调** | **A 冰层科考**（深蓝底 + 瓷白面板 + 冰晶青） | 用户追加要求：**页面底部做随纪元变化的动图**。见第 1 节 |
| **布局** | **自适应双模** | 桌面三栏 / 平板两栏 / 手机单列 + 底部 tab，同一套 DOM 断点切换 |
| **图标** | **先占位后补图** | 先色块 + 文字标签，等方向彻底定稿再补图形。不阻塞 P1 |
| **动效** | **轻环境动效** | 平时克制，只有数字滚动、进度条、背景一层缓慢位移 |

**为什么选 A**：这套游戏一局可能挂几小时，深色沉浸但正文要-readable，瓷白面板正好保住可读性；
图标走线稿就能用内联 SVG 现画，不用等外部美术资源。

## 1. 纪元母题层：背景随纪元推进（用户追加的需求）

### 1.1 这是我的判断，不是随手答应

动态背景是**全游戏唯一一个"玩家挂机时也在变"的东西**。
数字会涨、进度条会动，但只有背景能把"这个文明走到哪一步了"这件事**不用读字就感受得到**。
配合本作"主打科技发展"的定位，背景就是一条**外化的科技进度条**——这是最值钱的一处视觉投资。

**但必须做成"母题层"而不是"特效"**，三条约束：

| 约束 | 做法 |
|---|---|
| ① 切换纪元 ≠ 换图片 | 只是换一组 **CSS 变量 + 开关某个图层**。JS 里加一个纪元，只改 CSS，不动架构 |
| ② 性能预算硬顶 | 见第 5 节。背景必须有"降级到静态"的开关 |
| ③ 不抢前景 | 背景层永远 `z-index` 最低、`opacity` 上限 0.6，前景白面板盖在上面保证对比度 |

### 1.2 五个纪元的视觉母题

| 纪元 | 光色 | 母题元素 | 情绪 | 实现难度 |
|---|---|---|---|---|
| **暗流** | 最低 | 两点微弱冷光 + 极慢上浮的微粒（菌毯碎屑）。几乎全黑，只有采集时才有一瞬亮 | 冷、静、空 | 低 |
| **冷焰** | 低 → 中 | 生物发光的缓慢光晕从面板边缘渗出，青绿色。点"采集"时有一下呼吸 | 第一次有"活气" | 低 |
| **硫泉** | 中 → 暖 | 底部升起热液的暖色气泡与扰动，橙色从下往上涨 | 第一次有"热" | 中 |
| **洋流** | 中 → 冷 | 横向流动的洋流线条 + 冰壳方向的一束冷光自上而下 | 开阔、远 | 中 |
| **破壳** | 最高 | 冰裂纹自中央扩散，木星圆盘自上方沉入，金橙色铺满 | 终局 | 高（仅终局一次，值得） |

> **关键节奏**：光色从暗流到破壳**逐级变亮**。玩家挂机不动也能看见"我这个文明变亮了"。
> 终结画面 = 冰裂 + 木星，对应 `EUROPA_SETTING_v0.1.md` 第 7 节的 11.89° 角直径。

### 1.3 分钟级与秒级两层动

| 层 | 周期 | 内容 |
|---|---|---|
| **分钟级**（纪元层） | 数十秒到数分钟 | 光色、母题元素密度、整体亮度。玩家跨纪元时**自然察觉** |
| **秒级**（反馈层） | 1–3 秒 | 点采集的微亮、科技揭示的一次脉冲、建筑落成的涟漪 |

只有这两层的区分，才不会把"背景一直动"变成晕眩。

### 1.4 活图层：底图不动，动的是元素（v0.1.1 追加）

背景不是"每隔几秒换一张图"，而是**同一张底图 + 一层会动的元素**。
这既是观感选择，也是唯一能在预算内做到 24/7 常驻的做法。

#### 1.4.1 结构性决策：会动的东西不能画进图里

底图一旦画完就不再重绘，因此**图里画死的东西永远动不了**。
任何需要移动的视觉元素（生物、灯光、粒子）必须是**独立 DOM 层**，浮在底图上方。

```
┌───────────────────────────┐
│ 底图层（静态，画完即止）    │  ← 渐变、母题轮廓、地形
├───────────────────────────┤
│ 元素层（transform 动）      │  ← 深海种横移、洋流带、微粒
├───────────────────────────┤
│ 灯光层（opacity 动）        │  ← 聚落窗光，亮灭
└───────────────────────────┘
```

这三条的代价完全不同，见 §5.1。

#### 1.4.2 两类元素的实现硬性约束

| 元素 | 允许 | 禁止 | 理由 |
|---|---|---|---|
| **深海种 / 洋流带** | `transform: translateX/scaleY` | 改 `left` / `width` | 改 left 触发 Layout（重排），改 transform 只走 Composite |
| **聚落窗光** | 叠一层光斑改 `opacity` | 动 `background-color` / `box-shadow` | 改色 = 每帧 Paint；opacity = 跳过 Paint |

> **窗光特别说明**：光斑本身用 `radial-gradient` 静态绘制（不是 `box-shadow` 也不是
> `filter: blur`）。原因见 §5.1 的"重绘在主线程"——`box-shadow` 与 `filter` 会让
> 光斑的绘制进入每帧成本，而渐变是一次画完的位图。

#### 1.4.3 灯数上限与错峰

- **灯数上限 12**。每盏灯一个合成层，12 层约占 0.3MB 显存，可接受；再加就要考虑合并到一张精灵图。
- **必须错峰**：每盏 `animation-delay` 互不相同（原型用 `-i*1.7s`）。
  若所有灯同时熄灭，浏览器会在**同一帧**里堆 12 次合成层更新，产生一次可感知的顿挫。
- 潮汐相位低时不是逐盏改 opacity，而是给容器加一个 class 批量处理
  （`.lamp.tide-low i:nth-child(n+5){opacity:.06}`），**一次 DOM 变更**，浏览器自动批处理。

#### 1.4.4 一个真实的坑：不要改 `animation-duration`

潮汐强弱理应影响深海种游动速度。但直接改 `animation-duration` 会**重启动画时间轴**，
画面上表现为每 7 秒"顿一下"——比不动还难看。

**改用密度代替速度**：潮汐强 → 微粒容器 opacity 提高（元素更显眼，暗示更活跃）；
潮汐弱 → 压低。视觉上仍是"活的在动"，但动画时间轴从不被打断。

#### 1.4.5 常驻动画的唯一合法长期形态

深海种与窗光是 **24/7 常驻**的。这是放置游戏，玩家会挂机很久，
所以常驻动画必须满足：

- 属性只限 `transform` / `opacity`（§5.2）
- 周期 ≥ 4 秒（窗光 5–8s，深海种 44–68s），落在 §1.3 的慢档
- `visibilitychange` 隐藏时全部停（原型已实现 `startTide` / `stopTide` 配对）
- 提供 §5.5 的降级链，低端机可退到"只有窗光、没有深海种"

## 3. 布局：自适应双模

同一套 DOM，断点切换。

| 断点 | 形态 | 结构 |
|---|---|---|
| **≥1024px** | 桌面三栏 | `grid-template-columns: 280px 1fr 360px`。左=资源，中=主面板，右=科技树 |
| **640–1023px** | 平板两栏 | 资源栏折为顶部横向条，右栏保留，主区居中 |
| **<640px** | 手机单列 | 单列滚动 + **底部 tab**（采集 / 建筑 / 科技 / 职业） |

**铁律**：
- 手机端**任何元素不得横向溢出**（沿用 EVE-IDLE 那套 hover 规范：纯 hover 信息在手机端用 ⓘ 图标给点按等价物）；
- 桌面 hover 装饰一律收进 `@media (hover: hover)`，并补 `:active` 给触屏即时反馈；
- 主 CTA（采集按钮）在手机端必须**拇指区**可达，固定底部。

## 4. 图标：占位阶段规范

定位：**色块 + 文字标签**，不抢戏，等方向定稿再补。

| 项 | 规范 |
|---|---|
| 尺寸 | 资源 20px / 建筑 24px / 科技 32px |
| 形态 | 圆角 4px 的纯色块，不加描边、不加渐变、不加图标 |
| 配色 | 用第 2.3 节资源色；无专属色的用 `--line` |
| 对齐 | 与文字基线对齐，行高 24px 时块垂直居中 |
| 命名 | 占位块加 `data-icon="<资源键>"`，将来换图形时按键替换，不改结构 |

**解锁门控也要在视觉上说清**：未解锁的资源/职业**完全不出现在 DOM 里**（不是隐藏，是不渲染），
避免玩家看见一堆灰图标猜含义。这与 `ERA_OVERVIEW_v0.2.md` §8 的"解锁前不出现在 UI"一致。

## 5. 动效与性能预算（规格版）

动态背景是这套视觉里唯一可能翻车的部分。本节是**可执行规格**，不是建议。
凡涉及背景层的改动，以本节为准。

### 5.1 渲染代价格表：属性决定代价

浏览器渲染管线五步：**Style → Layout → Paint → Composite**。

| 阶段 | 线程 | 代价 |
|---|---|---|
| Style 重算样式 | 主线程 | 低 |
| **Layout 重排** | 主线程 | **高** |
| **Paint 重绘** | 主线程 | **高** |
| Composite 合成 | **合成线程 / GPU** | 低 |

只有 `transform` 与 `opacity` 能被浏览器识别为"不改变像素内容、只改变摆放与透明度"，
从而**跳过 Layout 与 Paint，直接交给合成线程**。合成线程独立于主线程 ——
**主线程跑游戏逻辑时，合成线程照样能动画面**。这是整个性能方案的立论。

### 5.2 允许与禁止

| | 属性 / 做法 |
|---|---|
| **允许** | `transform: translate` / `scale` / `rotate`、`opacity`、静态径向渐变、纯色块 |
| **禁止** | 动画 `box-shadow`、`filter: blur` / `drop-shadow`、`background-position`、`width` / `top` / `margin` |
| **辉光** | 一律**预渲染**（2× 尺寸 PNG 或 CSS 径向渐变静态图），**不做实时模糊** |
| **实现手段** | 优先 **CSS `@keyframes`**（可跑在合成线程），**不用 `requestAnimationFrame`** 驱动常驻动画 —— rAF 每帧都要过主线程 |

### 5.3 预算的推导（不是拍脑袋）

| 项 | 数字 | 推导 |
|---|---|---|
| 单帧总预算 | 16.6ms | 60fps |
| **背景单帧预算** | **≤2ms** | 60fps 的 1/8；其余 14.6ms 留给离线结算、科技树重绘、数值滚动 |
| **粒子上限 · 桌面** | **≤120** | 单个 2–5px 粒子合成一次 ≈0.015ms → 120 × 0.015 ≈ **1.8ms**，贴顶 |
| **粒子上限 · 移动** | **≤40** | 手机 GPU 填充率约为桌面 1/3～1/4，同 1.8ms 反推 → 40 |
| **动画周期** | ≥7s | 常驻动画必须落在慢档（分钟级），快速动画只允许**事件触发**（秒级反馈层） |
| 粒子尺寸 | 2–5px | 越大填充率代价越高，上限 5px |

### 5.4 为什么对手机要命：发热是累积的

```
动画持续占用合成线程 → GPU/CPU 满载 → 功耗上升
  → 电池放电 → 机身升温 → 系统 thermal throttle
  → 帧率从 60 掉到 40、30
```

**头 3 分钟不烫不等于没问题**。20 分钟后降频，正好落在放置游戏最典型的使用场景（挂机）。
这类差评的形态不是"帧率低"，而是"玩久了手机烫 + 明显卡"。

### 5.5 降级链（四档，从高到低）

| 档 | 触发 | 表现 |
|---|---|---|
| 0 全开 | 默认 | 粒子按档位上限，全部动效 |
| 1 减半 | 低端机 / 屏幕宽度 <640 且 `hardwareConcurrency` ≤4 | 粒子减半 |
| 2 静态 | `visibilitychange` 隐藏 / 离线结算 / `?fx=off` / 系统 `prefers-reduced-motion` | 关 rAF，`animation-play-state: paused`，退静态底色 |
| 3 关闭 | 用户在设置里显式关 | 只留 `--bg-abyss` / `--bg-deep` 双层底色 |

设置项状态存 `localStorage`，键名 `tidebreak.fx`，值为 `full | reduced | off`。

### 5.6 落地检查清单

动到背景层时逐条过：

- [ ] 任何新增动画属性必须是 `transform` / `opacity`，否则不进背景层
- [ ] 粒子数由设备档位决定，不写死
- [ ] `visibilitychange` 隐藏 → 停一切动画（CSS `animation-play-state: paused`，rAF `cancelAnimationFrame`）
- [ ] 离线结算期间背景降档为静态
- [ ] `?fx=off` 与设置开关并存
- [ ] 首屏：背景层 `z-index:0`，不可见时不启动动画
- [ ] 验收：DevTools Performance 连续录制 20s，Main 线程占用 < 20%
- [ ] 验收：**真机**（非模拟器）连续挂 20 分钟，机身不烫、帧率不掉

### 5.7 原型现状逐项对照

对象：`visual-proto.html`。

| 项 | 状态 | 说明 |
|---|---|---|
| 只动 transform / opacity | ✅ 合规 | `drift` / `breathe` / `flow` / `swim` / `flicker` 均在允许列表内 |
| 辉光为静态图 | ✅ 合规 | `.halo` / `.jupiter` / `.lamp i` 用径向渐变，全文件 `filter:` 计数 0、`box-shadow` 仅 1 处且在静态 UI 面板上 |
| `pointer-events: none` | ✅ 合规 | 背景不吃点击 |
| 窗光不用 `box-shadow` | ✅ 合规 | 光斑为 `radial-gradient`，见 §1.4.2 |
| 灯错峰 | ✅ 合规 | -delay `-i*1.7s`，12 盏互不相同 |
| `visibilitychange` 暂停 | ✅ 已补 | `startTide` / `stopTide` 配对，切后台停 7s 相位计时 |
| 潮汐驱动元素密度 | ✅ 已补 | 弱相位给 `.lamp` 加 `tide-low`、压低 `.motes` opacity，不改 `animation-duration`（§1.4.4） |
| 粒子数 | ⚠️ 原型 14 | 仅演示密度感，正式值走 120 / 40 |
| `prefers-reduced-motion` | ❌ 缺 | 只查了 `?fx=off`，未查系统设置 |
| 设备分档 | ❌ 缺 | 硬编码 14，需改为分档 |

末两项属结构性缺失，**须在 P1 骨架落地时一并补上**，不要留到后期。

## 6. 与玩法的耦合点（优先于纯装饰）

背景不该只好看，要承担信息：

| 信息 | 表达方式 |
|---|---|
| **当前纪元** | 背景母题 + 光色（不需要读文字） |
| **氧化/还原耦合** | **上极（冰壳）与下极（海底）两侧各一条光带**，产能 = 两条光带的较弱一侧。直接把 `min(上,下)` 画出来 |
| **热液丘熄灭危机** | 硫泉纪后期背景的暖色缓慢褪色 —— 减寿但不制造压迫感 |
| **破壳进度** | 冰壳裂纹随进度从中心蔓延（测天之后可见） |

> 第 2 条是本作独有的：**把核心机制画成两条光带**。玩家不用看公式就知道"哪边短了"。
