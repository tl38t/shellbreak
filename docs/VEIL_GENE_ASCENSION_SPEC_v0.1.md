### 2.2 状态字段（存档结构零改动）

`meta.veil.paths.gene` 由 `normalizeMeta` 收口为对象，并按两个分支与八个节点做白名单和 `0..3` 等级清洗（`state.js:816-840`、`prestige.js:479/483/485`）：

```js
meta.veil.paths.gene = {
  supreme: { lore: 0, valor: 0, agility: 0, longevity: 0 },   // 至高线
  pure:    { morph: 0, growth: 0, fastmat: 0, forge: 0 }      // 纯净线
};
```

- 等级一律 `0..3`，读档时 `clamp + floor`；缺字段按 0，绝不产 `NaN`（照抄 `veil-effects.js:29-35` 的 `lv()` 防御）。
- **不许**把 gene 等级写进 `s.perk`——那是当局字段，`freshRun` 会清空；基因改造是跨周目永久的。
- 节点等级只保存在 `meta.veil.paths.gene`，不会写入当局 `s.perk`；升级会扣除 `meta.veil.points` 并保存。

### 2.3 定价口径（2026-11-19 拍板：**单级价**）

用户给定 1 / 3 / 5 = **每一级的单级价**，逐级购买（Lv1 付 1、Lv2 再付 3、Lv3 再付 5）：

| 口径 | 单节点满级 | 8 节点全满 | 单跳门槛 |
|---|---|---|---|
| **单级价（已拍）** | **9 点** | **72 点** | Lv1=1 / Lv2=3 / **Lv3=5** |
| 累计价（未选） | 5 点 | 40 点 | Lv1=1 / Lv2=+2 / Lv3=+2 |

先例 `prestige.js:565` 的 `p.costs` 分级商品正是单级价（"3/6/12 即各单级价、不累计"）。
飞升点余额跨掀幕累积：每重获得的本周期点数加进旧余额，购买时扣减余额。因此 Lv3 的 5 点是购买前的余额门槛，玩家可以跨多重攒够，不要求单个周期产出 5 点。
现网本周期新增点数公式 `prestige.js:393`：`points = round(cycleTide/10000 + cycleStar/1000, 2)`，首次约 1.x 点；最终余额为旧余额加本次新增值。
全树 72 点总价对应的周期数，取决于各重新增点数、节点购买时机及广告奖励，属于**标定层**，本稿不预设固定重数。

### 2.4 双线共鸣（2026-11-19 新增）

按两条基因线**实际投入的飞升点总额**计算：每次升级分别扣 1 / 3 / 5 点，节点达到 Lv1/Lv2/Lv3 后累计投入分别为 1 / 4 / 9 点。
每条线将四个节点的累计实付相加；例如一个 Lv1 节点加一个 Lv2 节点为 `1+4=5`，四个 Lv1 节点为 `4`。
共鸣比较的是已投入总额，不读取当前余额，也不把开启路径的条件算作投入。

设至高线与纯净线投入分别为 `S`、`P`：

| 条件 | 全部基因节点效果强度 |
|---|---:|
| `S = P > 0` | 和谐 · ×2（效果增量 +100%） |
| `0.5 < min(S,P) / max(S,P) < 1` | 有缺 · ×1.5（效果增量 +50%） |
| 其他情况 | 失衡 · ×1（无额外加成） |

两线都未投入时为失衡；投入比恰好为 0.5 时也是失衡，必须严格超过一半才进入有缺状态。这个系数放大**基因节点本身的效果量**：
产出加成、消耗/风险削减和 Lv3 义体额外效果都按同一系数放大；例如 Lv3 义体额外 +20% 在两线共鸣时变为 +30%，投入相等时变为 +40%。
它不改变节点价格或其他系统的独立加成。界面同时显示两线投入总额、当前加成和触发规则。

**冰封 / 取暖的量纲锁定（写进验收）**：

- 冰封降的是**掷骰概率**，不是死亡人数：
  `perStepRisk' = CFG.FREEZE_CHANCE × (1 − warmCap(s)×2) × 0.1 × (1 − geneCut)`，
  `geneCut` ∈ {0, 0.10, 0.20, 0.40}。在线 / 离线两处必须逐字同式，否则线上/offline 口径分裂（项目反复栽过）。
- 取暖降的是 `warmRate()` 的**返回值**：
  `warmRate'(s) = warmRate(s) × (1 − geneCut)`。
  注意它有三类读点：`economy.js:963/974`（扣暖石 / need）、`game.js:1836`（离线）、
  `render-environment.js:130/153`（面板）。**必须改在 `warmRate()` 内部**，不能只改调用点，
  否则出现"面板烧 1.0/s、实际 0.6/s"。

### 6.1 顺序耦合：第 1 次飞升就开基因 ⇒ 3 个 Lv3 空转（已拍 A）

勇武 / 敏捷 / 延命三个 Lv3 读到的义体等级全为 0 ⇒ 花了点数没效果。
（学识 Lv3 依赖 `vo` 四信条，用户 2026-11-19 明示**先不管**，见 §6.0。）

**时间线核算（证明这不是理论风险）**：

| 事实 | 代码 |
|---|---|
| 掀幕清 `perks / cycleTide / cycleStar`，飞升点余额保留并累加本次 `gained`；**`v.paths` 一字不动** ⇒ 路径等级跨重永久保留 | `prestige.js:doVeil` |
| 每重新增点数按周期累计计算（首次约 1.x 点），余额按分累加，节点购买再扣除 | `prestige.js:doVeil`、`prestige.js:393` |
| 三个 Lv3 全满需 **27 点**（单级价，每节点 9 点）⇒ 约 20+ 重 | §2.3 |

⇒ 玩家可以全程选基因 / 虚境、从不开机械飞升，跨十多重把三个 Lv3 买满而**一直空转**；
点数永久花掉，效果要等某次终于开了 `si` 才生效。

| 选项 | 做法 | 后果 |
|---|---|---|
| **A（2026-11-19 已拍板）** | 数值：基因 Lv3 读当前 `si` 义体状态，**未开即 0**。UI：**不写任何"需同步开启"提示**——机械飞升未开时，联动半句「XX 义体额外提供 20% 效果」**整句不渲染**；已开后才追加 | 保留联动语义；玩家看不到未生效的承诺，不算暗坑。代价：第一次开基因的玩家仍会买到暂时空转的 Lv3（但无提示误导） |
| B（未选） | 基因 Lv3 改为自增独立乘区，不读 si 实际等级 | 无空转；但"XX 义体额外 +20%"的联动语义消失，等于删掉用户要的设计 |
| C（未选） | 限制基因开启顺序 | ⚠️ 原写法"基因只能第 2/3 次飞升才开"**不成立**：若第 1 次开虚境，第 2 次开基因时 `si` 仍未开。要真正成立必须改成"`si` 已开是基因可选的前置条件"——硬依赖，推翻 `VEIL_HUB_SPEC §2` 三选一自由 |

### 6.2 "额外 +20% 效果"逐器官算式歧义（静默 bug 高发区）

七个器官的现有效果**形状不同**，"效果 +20%"不能统一写成 `×1.2`：

| 器官 | 当前效果（`veil-effects.js`） | Lv3 现值 | 放大口径应写成 | 若粗暴 `×1.2` 会怎样 |
|---|---|---|---|---|
| 鳞 `scale` | `recipeCraft` 加法轴 | `+2` | `+2.4`（加法轴放大 20%） | 尚可（结果同） |
| 眼 `eye` | 同上 | `+2` | `+2.4` | 尚可 |
| 手 `hand` | 同上 | `+2` | `+2.4` | — |
| 心 `heart` | `craftExtraMul` 独立乘区 | `×2.5` | `1+(2.5−1)×1.2 = ×2.8` | `×3.0`（把整段乘 1.2，口径与加法轴不一致） |
| 尾 `tail` | `hydroOutMul` 产出乘区 | `×2.5` | `×2.8` | 同上 |
| 脑 `brain` | `softCostMul` **降耗**乘区 | `×0.4` | `1−(1−0.4)×1.2 = ×0.28`（降得更多） | **→ ×0.48，反而消耗变多，方向反了** |
| 胃 `stomach` | `foodNeedMul`/`luxNeedMul`/`birthTimeMul` **降耗** | `×0.3` | `×0.24` | **→ ×0.36，方向反了** |

**统一口径（2026-11-19 已拍）："效果量 × 1.2"**——三类形状归为同一句话：这个器官的效果强度放大 20%。

| 形状 | 算式 | Lv3 基因放大后 |
|---|---|---|
| 加法轴（鳞 / 眼 / 手） | `add × 1.2` | `+2 → +2.4` |
| 产出乘区（心 / 尾） | `1 + (mult − 1) × 1.2` | `×2.5 → ×2.8` |
| 降耗乘区（脑 / 胃） | `1 − (1 − mult) × 1.2` | `×0.4 → ×0.28`、`×0.3 → ×0.24` |

**附加项不吃（2026-11-19 已拍）**：Lv3 的独立赠品——鳞/眼/手 `starPerBldgPct`、
心 `terraformTimeMul ×0.5`、尾 `drillSpeedMul ×3`、脑 `passiveShellMul ×2`——全部保持原值，只放大主效果。

> 实施纪律：在 `veil-effects.js` 新造一层"基因放大系数"访问器（例如 `SB.veilFx.geneAmp(id)`），
> 由各器官函数自己读取，**不在 gene 侧直接改 organ 等级**；否则跨路径写回会污染存档。

## 7. 其余待拍（不定就没法写表结构）

1. **档位语义（2026-11-19 拍板：全部替换型 / 取当前级）**：表里百分比 = **到该级的最终值**，
   Lv3 不叠加 Lv1/Lv2。至高 Lv3 商人 = +120%（不是 +240%）、纯净 Lv3 生体锻炉 = +240%（不是 +420%）。
   与硅基硬纪律一致（`veil-effects.js:13-14`："替换型取当前级，叠加会越过 100%"）。
   实施时全部用 `pick([0, v1, v2, v3], lv)` 取值器，与 `veil-effects.js:37` 同形状；**禁止累加**。
2. **建筑升级倍率 −10/20/30%（2026-11-19 拍板：只降增量）**：
   `costOf` 用 `Math.pow(b.ratio, effN)`（`economy.js:757`，ratio 是建筑自带、默认约 1.15）。
   - **已拍：只降超出 1 的增量** ⇒ `ratio' = 1 + (ratio − 1) × (1 − geneCut)`，Lv3（−30%）⇒ `1.15 → 1.105`。
     实测 10 级造价倍率 `4.0456 → 2.7141` = 原版 **67.1%**（降 32.9%）；5 级降 18.1%、1 级降 3.9%。
     升级仍是递增曲线（底数 > 1），不破坏单调性。
   - 否决"降 ratio 本身"：`1.15 × 0.7 = 0.805 < 1` ⇒ 等级越高越便宜 ⇒ 数值崩坏，属结构错误非标定。
   - **与 ERA9 G.E.E.K / 泰拉改造无冲突（原"相加/相乘"疑问作废）**：后者改的是**指数**
     `_effN = max(0, n − offset)`（`economy.js:731`，仅 `COST_OFFSET_COVERED` 那批建筑），
     本项改的是**底数** `ratio`；两者落在 `Math.pow(base, exponent)` 的不同参数位，天然共存，
     无需拍叠加方式。两处仍需各自在 `costOf` 内实现以保持面板 === 扣费同源。
3. **冰封死亡率双路径**：`economy-tick.js:608` 与 `offline-scheduler.js:201` 同一公式写了两遍，必须同时改。
4. **取暖消耗多读点**：`warmRate` 有结算（`:963/:974`）、离线（`game.js:1836`）、面板（`render-environment.js:130/153`）三类读点，
   改在函数内部才是单一落点。
5. **飞升点定价口径**：已拍单级价（§2.3），无待拍。飞升点余额跨重累积，Lv3 单跳 5 点可分多重攒够；遗留标定题是新增点数曲线和全树 72 点总价对应的成长节奏，本稿不碰。
6. **商人产出的定义域（2026-11-19 拍板：只管奢侈品 S）**：
   代码里"商人产出"分三段——奢侈品供给 S（`economy.js:466-520`）、科学副产与市政副产（`:515-527`）。
   延命线的"商人 +40/80/120%"**只乘奢侈品供给 S**，与 `luxuryPactMul`（`economy.js:1087`）同一落点，
   **不吃科学 / 市政副产**。理由：①副产是《中世纪集市》的附赠，玩家语境里"商人产出"指主业奢侈品；
   ②副产若跟着加成，会与学识线的学者 / 书手加成互相渗透、叠出边界值。
   实施时新造 gene 独立乘区乘在 S 上，不并入 `s.perk.luxuryPact` 加法轴（跨周目 vs 当局，来源不同）。
7. **藻食范围（2026-11-19 拍板：职业侧 + 建筑侧都乘）**：
   `foodRate()` 里藻食有两条来源——建筑侧藻场 `byBuild`（`economy.js:1451-1453`）、
   职业侧采集者 `byJob`（`:1462-1464`，唯一吃 `algaeCropMul` 的那条），相加后走公共乘区（`:1471`）。
   gene 加成**新造独立乘区乘在 `foodRate()` 整段返回值上**（`:1471` 那一行），
   这样两侧同时吃到，且 tick 与 rates 共用 `foodRate()` ⇒ 面板 === 结算天然成立。
   **不复用 `algaeCropMul`**（那是当局 perk、只管职业侧；gene 是跨周目 meta，定义域不同）。
   ⚠️ 珊瑚无独立建筑侧：`coralFarmMul`（`economy.js:1029`）是珊瑚林建筑对**珊瑚匠职业**的加成，
   仍乘在珊瑚匠行（`economy-tick.js:136-140`）；gene 珊瑚加成直接乘这条职业行即全覆盖。
8. **动态文案**：Lv3 才追加的那半句如何参与 i18n——按 `AGENTS.md:6`，先登
   `outputs/.../i18n_text_inventory.xlsx` 并给语义 key，代码引用 key 不写字面量。
