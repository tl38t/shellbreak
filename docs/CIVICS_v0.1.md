## 1. 参照：Civ6 远古市政树

⚠️ 来源说明：用户指定的 `civ6hd.com/.../CIVIC_EARLY_WARFARE_HD.html` 那页只导出**一张卡**
（原始军事 / 30 文化 / 鼓舞＝建造或购买 3 个军事单位 / 解锁：市政树）。远古七项的全貌
取自 Civ6 wiki「Civic」条目的远古段，两张对照后形状一致，可用。

| 市政 | 文化 | 解锁的政策卡 | 鼓舞（一次性文化） |
|---|---|---|---|
| 法典 Code of Laws | 40 | 调查 / 纪律 / 城市规划 / 君主崇拜 | 改良 3 块地 |
| 技艺 Craftsmanship | 40 | 劳役 / 斯巴达教育 | 建造或购买 3 个军事单位 |
| 对外贸易 Foreign Trade | 40 | 古商 / 海运业 / 商队驿站 | 发现第二块大陆（开放贸易路线） |
| 军事传统 Military Tradition | 50 | 将军 / 机动 | 清除一个蛮族前哨 |
| 国家劳动力 State Workforce | 70 | 征兵 / 强迫劳役 | 建成一个区域 |
| 帝国初期 Early Empire | 70 | 殖民 / 土地测量员 | 人口达到 6 |
| 神秘主义 Mysticism | 50 | 神谕 / 鼓舞 / 启示 | 创立万神殿 |

**三条必须照搬的机制**（比「名字像不像」重要得多）：

1. **文化是独立资源**，与科技分属两个池子 ⇒ 两条树可以错开冲刺。
2. **市政树与科技树平行**，各自的前置逻辑不同。
3. **鼓舞＝每项市政挂一个 side-quest**，完成瞬间返一笔文化。
   Civ6 的官方描述是「正常玩的同时获得提升，操作决定遇到哪种」——
   它的作用是**防止市政线永远落后于科技线**，是本作尤里卡（eureka）的兄弟机制。

## 2. 本作四条硬约束（决定哪些能迁、哪些不能）

| # | 约束 | 后果 |
|---|---|---|
| 1 | **没有文化资源线**。RESS 仅 9 项：藻食 / 珊瑚 / 石头 / 金属 / 暖石 / 骨材 / 精铁 / 科技 / 地热 | 市政点要么新开资源，要么从现有资源切 ⇒ 这是第一道分叉 |
| 2 | **没有城市、地格、区域** | Civ6 的文化来自城市与区域建筑。本作产出全由「人口 × 职业 × 建筑」给出 ⇒ 文化得另找出处 |
| 3 | **没有军事单位** | 原始军事 / 纪律 / 斯巴达教育 / 将军 / 征兵 等全部排除。本作是纯放置经营 |
| 4 | **era1 的瓶颈不是科技，是人口** | 2026-09-27 两次实测：① 点价 ×8.7（330→2875）⇒ 整局仅 +0.38h；② 石屋 ratio 1.15→2.5 ⇒ 整局 +2.68h。 ⇒ **任何只给「科技 +X%」的市政卡在 era1 都是废卡** |

⇒ 推论：**era1 的市政卡必须解 era1 自己的瓶颈**，否则玩家学完即过期。
这是选卡的唯一筛子，不是「哪个名字更贴切」。

## 3. 市政点怎么来 —— **已拍板：书手（主）+ 议事厅（少量）**

> 2026-09-27 用户口径：**「新增书手这个职业可以获得市政点，然后议事厅本身也给少量市政点。」**
> 这**否掉了下面原推荐的方案 B**（议事厅独产），改成**双来源**：职业侧为主、建筑侧为辅。
> ⚠️ 原 A / B / C 三方案保留作对照，只有 B 的「议事厅独产」被这一句否掉了。

### 3.1 来源一：书手（主）

`culture += jobs.scribe × UNIT.culture`（速率待拍）

- ✅ **叙事闭环**：学者探求真知（科技线）、书手抄录编纂（市政线）——本作两种知识活动
  本来就该有两种人，比「一个职业干两件事」好讲
- ✅ 与科技线**不同源**：书手吃人口但不吃学者，两条树有错峰的可能
- ❌ **Civ6 无对位**：Civ6 的文化来自剧院广场 / 奇观 / 政策卡 / 城邦 / 信仰，
  **没有任何「人口职业直接产文化」的机制**（最接近的只有大文豪这类个别单位）。
  ⇒ **数值不能用 Civ6 校验，只能自己标定**，别拿「Civ6 远古 40 点一张卡」去推书手速率。
- ⚠️ **与学者是抢人口的对手，不是兄弟**：本作 era1 的瓶颈就是人口（约束 4）。
  加职业 = 从采集者 / 珊瑚匠 / 匠人手里抽人 ⇒ 会压慢整局。今天已有实证：
  住房 ratio 一档的改动就带来 +56% 整局时长。

### 3.2 来源二：议事厅（少量）

`culture += hallLevel × K`（K 待拍，用户口径「少量」）

- 它的主要意义不是产出，是**兑现第 0 节那条欠账**——议事厅本来就该是开会的地方
- ⚠️ 与《典章·规约》那类「建筑成本 −X%」的市政卡是**同一件事的两半**，归属必须先分
  （见 §6 第 6 条），不能各写一半
- ⚠️ 它现在身上挂着的是「所有建筑下一级成本 −2%/级」（实现在 `economy.costOf`），
  与产文化**不冲突**，但要写清「这座建筑既降成本又产文化」还是「降成本那条移交市政卡」

### 3.3 一个代价：两条来源都是线性 ⇒ 形状变单一

书手线性于**人口**、议事厅线性于**等级**，两个都是一次函数，合起来还是线性。
原本方案 B 那份「线性（建筑）× 指数（科技 ratio）」的曲线对比没有了。

要补回形状差异，可选：`hall` 的产出系数按等级走 ratio（另设一个系数，别复用建造用的 ratio 1.20），
或给书手加一个只增不减的乘区。**两条都待拍。**

### 3.4 代价：加一个职业的真实落点

| 文件 | 内容 | 漏了会怎样 |
|---|---|---|
| `src/config.js:617` | `JOBS` 数组加一项 | — |
| `src/folk.js:17` | **第二份字面量职业清单** `IDS` | UI 雇得到、**配工引擎看不见**（人派进去不出产） |
| `src/state.js:61` | `jobs` 默认表加键 | `undefined` ⇒ NaN |
| `src/economy.js` | tick 产出行 + `rates()` 同式 | 面板与实收打架 |
| `src/techs.js` | 加一项 `eff.unlockJob:['scribe']` | 职业永远雇不了（解锁机制现成，不用新造） |
| `sim/e2e.mjs:957` | **bot 配工权重表** | ⚠️ 见下 |
| `sim/e2e.mjs:1089` | 职业夹具 |  same |

> ⚠️ **最易漏的一条：新职业不在 bot 的配工权重表里 ⇒ 它在回归里等于不存在。**
> `sim/e2e.mjs:957-958` 那张表是**写死六项**的

> 判据：`folk.js` 的 `IDS` 与 `e2e` 的权重表是**两份独立的表**，改职业要一起改。

### 方案 A · 学者分流（已否）
`culture += scholarScience × r`（r 待拍，如 0.25）

- ✅ 零新资源线（RESS 不加键，避开「加 id 要改 5 处」那条判据）
- ✅ 语义最贴：结绳 → 书写 → 议政，本作叙事链本来就通到这儿
- ✅ 放置游戏零操作负担（本作玩家不手动分职业）
- ❌ 与科技争同一批人：科技慢 ⇒ 文化也慢 ⇒ 两条树永远同步，丢掉 Civ6 的错峰张力
- ❌ 分流比例是硬编码，后期学者多了两条线一起膨胀，容易脱钩

### 方案 B · 议事厅存量产文化（**已被拍板否掉**）
`culture += hallLevel × K × popFactor`（K 待拍）
> 否掉的原因：用户给出的新口径是「新增书手职业产市政点 + 议事厅给少量」，议事厅从**主来源**
> 降级为**辅来源**。方案本身没坏，只是不再是唯一来源。上面 §3 那版就是它。

- ✅ **叙事闭环**：议事厅本来就是「开会的地方」，文化从它来，正好兑现第 0 节那条欠账
- ✅ **天然 gate**：hall 由石工（层四）解锁 ⇒ 与「era1 科技后期才能开」天然对齐，不用另造门槛
- ✅ **不跟科技争人**：culture 不受学者数量影响，两条线真正独立
- ✅ **曲线对比鲜明**：hall 是线性、科技是指数 ratio，两种增长形状并存更好看
- ✅ 给了一类**「只花钱不直接产出」的建筑**一个位置——本作现有建筑全是产能件，缺这一类
- ❌ 要新增 RESS 键 `culture` ⇒ 落点约 53 处（以 warmstone 实测），含 `CAP_BASE` / `state.res` /
  `state.got` / `economy.rates` / `render` / `e2e` 六文件

### 方案 C · 用现有资源直接买
- ✅ 零新增
- ❌ 没有成长曲线，后期市政卡会变成「已解锁即免费」
- ❌ 表达不出 Civ6 那条「文化攒了十年、一朝解锁市政」的手感

### 我的推荐（已被用户推翻）

原推荐是方案 B，唯一最硬的理由：它是唯一一个**不把市政点挂到「学者」身上**的方案，
而 era1 的瓶颈恰恰在人口不在科技（约束 4）；方案 A 会让两条树永远同步，等于没开第二条线。

**用户已拍「书手 + 议事厅双来源」，实现了同样的目的（不挂到学者身上）但多了一个职业。**
上面 §3 的落点表与 §6 的待拍项按新口径重写。代价仍是那 53 处，但多出 `folk.js` / `e2e` 两张表。

## 4. 第二道分叉：市政树怎么解锁

用户口径「从 era1 科技后期才能开启」。两条路：

| 做法 | 内容 | 评价 |
|---|---|---|
| P1 | 议事厅建成即开（等价于 hall 的 requiredTech = 石工） | 最省，与 hall 的既有定位一致 |
| P2 | 石工 **+ 已掌握 N 项 era1 科技**（如关键节点 历法 + 书写 + 石工） | 更像「制度成型」，但多一道门槛，且 N 值又要标定 |

建议 **P1**。理由：石工的 cond 已经是「石头 100」，这本身就是个不轻的门槛；
再加科技数就是三重 gate，而 era1 时长已经证明对 gate 敏感（住房 ratio 那次 +56%）。

## 5. 三个市政与卡（筛子 = 解 era1 瓶颈）

数值全部 `待拍`，此处只给形状。

### 市政一《结社》〔人怎么在一起干活〕
- **文化成本**：待拍（对标 Civ6 法典 40）
- **卡〔分工〕**：职业产出 +X%
  → 解 era1 职业产出瓶颈。对标 Civ6 技艺 / 斯巴达教育
- **卡〔轮值〕**：手动采集 +X%
  → ⚠️ era1 用不上（era1 后期玩家已经不手动点了），**是 era2 开局的救命卡**。
    留着是给 era2 的，不是 era1 的（对标 Civ6 调查）
- **鼓舞**：建成第 6 座藻场（对标「改良 3 块地」）
  → 复现现有 cond：`{t:'built', b:'kelp', n:6}`

### 市政二《典章》〔把规矩定下来〕
- **文化成本**：待拍
- **卡〔规约〕**：所有建筑下一级成本 −X%/级
  → 解 era1 末期建筑成本陡升。⚠️ **与议事厅现存那条「−2%/级」是同一件事的两半**，
    要么市政卡接管、议事厅改回纯文化建筑，要么两者相加并写清归属——**不能各写一半**
- **卡〔口粮〕**：藻食消耗 −X%
  → 直解 era1 食物瓶颈。对标 Civ6 帝国初期 / 强迫劳役
- **鼓舞**：人口达到 N（对标「人口达到 6」）
  → 复现现有 cond：`{t:'pop', n:N}`

### 市政三《匠作》〔手艺怎么传〕
- **文化成本**：待拍
- **卡〔模铸〕**：工坊（青铜术解锁）相关效果 +X%/级
  → 工坊是 era1 末段才出现的加工件，正好接得上
- **卡〔备料〕**：建筑成本中的二级材料（石头 / 金属）需求 −X%
  → 解 2026-09-27 已记的那条：**石头线建筑出口只剩议事厅，采石工产出永久囤积**
- **鼓舞**：掌握「海潮占卜」（对标创立万神殿）
  → 复现现有 cond：`{t:'res'}` 类，或改挂 tech 台账

### 关于「鼓舞」的实现成本

`tech.js` 的 `condMet` 已有 12 种条件：`default / built / total / res / gathered / rate /
pop / job / techs / coef / eraTechs`。上面三个鼓舞**全部能用现成 cond 表达**，
`condShort()` 也已经有了（UI 的「还差多少」）⇒ 鼓舞是**零新机制**，
只需要「cond 达成 → 一次性发文化」这一个小钩子。

## 8. 三个市政的拍板版 + 核对结果（2026-09-27 用户提出，**未落地，先核问题**）

### 8.0 用户口径原文

> 对标科技点（市政点速率）；要做**鼓舞**（对标尤里卡，只揭示市政、不填充 50%）、**政策卡**、**政体**。
> 三个市政：**法典**（0 市政点，基础，无需鼓舞，解锁政体「酋邦制」）→ 酋邦制：+5/s 藻食、
> 两个政策卡槽；**技艺**（100 市政点，鼓舞＝工坊 1 级，解锁政策卡「技艺」：工坊各项发明消耗 −5%）；
> **神秘主义**（100 市政点，鼓舞＝完成科技海潮占卜，解锁政策卡「神秘主义」：科技产出 +1/s）。
> 调整一次政策卡，消耗「当前最高完成的市政」的 cost；调整一次政体，消耗两倍。

### 8.1 ⚠️ 三张卡不在一个量级：两个断层、一个约等于零

本作基准（2026-09-27 实拉 `economy.js:311-312` / `UNIT`）。
⚠️ 2026-09-27 用户批了一个 **+0.3/s**（未指明是哪一条，见 §8.7 第 6 条）：
+0.3 若给科技 ⇒ 仍是 2 个学者的产出、基准的 1~1.5 倍；若给藻食 ⇒ 只占基准的 11~20%，很温和。

| 卡 | 效果 | 本作基准 | 相对强度 |
|---|---|---|---|
| 酋邦制 | +5/s 藻食 | 职业侧 0.5/采集者/s、建筑侧 0.09/藻场级/s；典型局面（2-4 采集者 + 5-8 级藻场）≈ **1.5-2.7/s** | **+185%~+333%**（翻 2-3 倍） |
| 神秘主义 | +1/s 科技 | `UNIT.sci` 0.15/学者/s，2-3 学者 ≈ **0.3-0.45/s** | **+222%~+333%，等于凭空 6.67 个学者**；era1 全部科技仅 2875 点 ⇒ **+1/s 只要 48 分钟就白嫖整条科技线** |

⇒ 这不是「三个选择」，是**两个必选 + 一个玩具**。而且今天已实证：食物是人口的上游、
住房 ratio 动一档 = 整局 +56% ⇒ 酋邦制那条 +5/s 会把整局大幅**缩水**，与 era1 想拉长到 2h 的方向相反。

### 8.2 ✅ 鼓舞 = 揭示（**不等于解锁**）—— 2026-09-27 澄清，原判断作废

⚠️ 初版把「揭示」读成了「直接解锁市政」，于是判 100 点形同虚设 —— **这个判断是错的，撤回。**

⇒ **揭示只是让市政点可投入，不是免付。** 100 点的定价因此完好，鼓舞的价值是

⚠️ 但法典那条例外仍在：它 **cost 0 且无鼓舞** ⇒ 直接可见、直接研究，始终白送（Civ6 是 20 点）。

### 8.3 ✅ 换卡收费：两条我提错了，一条还悬着

把那句话展开成可执行规则：**换政策卡 = 付「当前已完成市政中 cost 最高的那个」的 cost；

## 10. 市政树改成横卷（2026-09-27，用户「市政树要做成科技树这样」）

第一版落地时树是**缩进列表**（`margin-left:14px` + 左竖线）。用户否掉：要科技树那种
(列 × 行) 的横卷 + 贝塞尔连线 + 卡片。已改。

### 10.1 复用了什么、没复用什

| 层 | 处置 |
|---|---|
| 几何算法 | **照抄同构**：`civics.layout()` 与 `tech.layout()` 逐行对应（列 = `layer`、行 = 排版产物、连线 = `reqs`） |
| 卡片尺寸 | **借 `SB.tech.geo`**，不另立一份 —— 两张树的卡片必须逐像素一样高 |
| CSS | **直接共用** `.techscroll` / `.techcanvas` / `.technode` / `.tel` / `.tntag` / `.minibar` |
| 容器 id | **独立** `civicScroll`（共用 id 会让拖动/滚动留存两边抢一个元素） |
| 滚动位置持久化 | **没做**：市政只有一个纪元、没有纪元跳转按钮，那一套 persist/restore 现在无用 |
| 纪元横幅 | **多于一个纪元才画**：单纪元横幅是纯噪音 |

### 10.2 数据侧新增 `layer`

`CIVICS` 的每项加了 `layer`（**列坐标，几何的唯一依据**）：

```
laws   layer:1   ┐ 根，独占第 0 列
craft  layer:2   ├ 同在第 1 列，一上一下（row 0 / row 1）
mystic layer:2   ┘
```

⚠️ 与 `techs.js` 同一条纪律：**形状必须落在数据里**。只写在注释里的「层」骗过一次人
（2026-09-26 科技树那次），所以 e2e 的「市政树几何」一节把三条节点的 (col, row) 钉住了
—— 加市政时若忘了给 `layer`，它会静默落回第 0 列与法典撞在一起。

### 10.3 卡片三态

| 态 | 标题 | 内容 | 按钮 |
|---|---|---|---|
| 已完成 | 真名 + 绿标「已完成」 | desc + 鼓舞已达成 | **不渲染**（不留假按钮） |
| 已揭示 | 真名 | desc + 鼓舞条件与进度 | 「研究 N」 |
| 未揭露 | 「未揭露的市政」 | 「达成鼓舞条件后揭示」+ 鼓舞条件 | 「研究 N」（灰） |

## 11. 政体与政策卡改成 Civ6 式（2026-09-27，用户「做成文明 6 那样」）

**这一轮只搬外壳**（用户三选一里挑的）：结构全上，但**不动数值、不强加类型约束、
不新增政体**。已核实 Civ6 的真机制（wiki + IGN）：

| Civ6 | 本作现状 |
|---|---|
| 政体自带**槽位配方**（部落制 1 军事+1 经济；法西斯 4+1+1+2） | ✅ 已改成配方 `slots: { type: n }` |
| 政体自带**独有被动** | ✅ 已有（酋邦制 = 藻食 +5/秒），面板上单独一行 |
| 政策卡分**军事/经济/外交/万能** | ⚠️ 砍到三类（见下），卡上带类型标签 |
| **万能槽**吃任意类型 | ✅ `cardFits` 实现，`sci` 卡进 `prod` 槽会被拒 |
| 换政策卡在完成市政当回合**免费** | ❌ **没照搬**：保持本作收费（首次免费 → 每次 1× → 换政体 2×） |
| 政体按层级解锁、槽位从 2 涨到 10 | ❌ era1 只有一条政体，机制照建等数据 |

### 11.1 槽位类型为什么是这三类

Civ6 的四类里，**军事**（没有军事单位）与**外交**（没有城邦）按约束 §2 直接排除。
剩下的按**经济职能**分，不按资源分：

```
wild 万能槽  吃一切
prod 工造槽  加工与建造
sci  科研槽  科技产出
grow 民生槽  人口与饮食
```

`grow` 此刻没有用户（era1 没有民生卡），**故意先建**：工坊内容那一轮大概率会造出
「解人口瓶颈」的卡（设计文档 §2 的筛子指的就是这种），到时候直接用它。

### 11.2 ⚠️ 类型约束此刻**不咬人**（是预期的，不是没做）

酋邦制给的是 **1 个万能槽**，而万能槽吃一切 ⇒ 技艺（工造）与神秘主义（科研）
**都能塞**。类型规则写进了代码、也有断言验证「工造槽装科研卡会被拒」，
但玩家在这一局里感受不到它。

**要让类型咬人，必须有至少一个非万能槽。** 而加第二个槽会撞上一个真限制：
**`s.card` 是单值，状态层只承载 1 个槽**。所以加槽是「配方 + 状态」两处一起改的活
（`s.card` → `s.cards: []`，`cardEver` 同理，`setCard`/`cardBlocked`/`flow`/渲染四处跟改）。
e2e 有一条断言把当前承载上限钉住了，改配方时它会先红。

### 11.3 顺带修掉的一处显示问题

`condShort` 的 `now` 可以大于 `need`（条件是「建成 1 级工坊」而工坊已 2 级），
照印会读成「超出上限、坏掉了」。`boostText` 因此在达成时改念条件本身。
