## 一、工坊的形态：上下两块

用户截图确认的样式（= 猫国 `js/jsx/left.jsx.js` 的工坊面板）：

```
┌─ 工艺制作效率: +5% ────────────────────── □ 隐藏已完成的升级 ─┐
│ ┌ 升级 ─────────────────────────────────────[−]┐           │
│ │ 青铜镰   已拥有          ← 买一次，永久，不能再买 │           │
│ │ 青铜斧   已拥有                               │           │
│ │ 青铜镐   已拥有                               │           │
│ └───────────────────────────────────────────┘           │
│ ┌ 工艺制作 ────────────────────────────────[−]┐           │
│ │ 石梁                                        │           │
│ │   材料：石头 100                            │           │
│ │   +1  +25  +100  100%    ← 可反复制造        │           │
│ └───────────────────────────────────────────┘           │
└──────────────────────────────────────────────────────────┘
```

**「工艺制作效率 +5%」是工坊顶部那一个数**，全局的、一个，不是每件东西各配一个按钮。

### 关于「手动还是自动」

- 手动：点了立刻结算，**不占人口、不需要职业** ⇒ era1 完全装得下。
- 猫国的自动路有两道闸：`mechanization` 科技 + 把匠人派去该配方（`assignCraftJob`，匠人仍占编）。
  没这两样 `model.assignCraftLinks = []`，按钮不出现。⇒ **先只做手动。**

## 二、石梁（工艺制作区唯一的配方）

### 2.1 换算与三条已定的性质

- 换算：**100 石头 = 1 石梁**（用户口径；猫国 1 梁 = 175 木材，本作略便宜）

| # | 议题 | 结论 | 日期 |
|---|---|---|---|
| 1 | 石梁占不占仓储上限 | **无上限**（跟猫国） | 已拍 |
| 2 | 石梁能否换回石头 | **不能**，单向 | 已拍 |
| 3 | 一次能造多少 | **跟猫国四颗按钮** | 已拍 |

### 2.2 猫国四颗按钮（对照，`js/jsx/left.jsx.js:502-505`）

| 按钮 | `craftFixed` | `craftPercent` | 实际造多少 |
|---|---|---|---|
| **+1** | 1 | 0.01 | `max(1, 库存能造的×1%)` |
| **+25** | 25 | 0.05 | `max(25, 库存能造的×5%)` |
| **+100** | 100 | 0.10 | `max(100, 库存能造的×10%)` |
| **MAX** | — | 1 | `craftAll()`：有多少造多少 |

公式 **`造多少 = max(固定下限, 库存能造数量 × 百分比)`**。

> ⚠️ **已验：百分比不是主效果，固定数才是**（用户追问「+100 就是 100 吧」——是的）。
> 验算（猫国 wood 配方 `{catnip: 100}`，`workshop.js:2120`）：
> 库存 15000 猫薄荷 ⇒ `allCount = 150` ⇒ `+100` 按钮 = `max(100, 15) = 100` ⇒ 扣 10000 得 100。
> **`+100` 就是 100。** 界面标签：前三颗显示 `+1 / +25 / +100`，第四颗显示 `100%`。

### 2.3 无上限的三个后果（已接受的代价，不是 bug）

1. 石头满仓后玩家可把石头全刷成石梁 ⇒ 仓库对石头的意义归零。
2. 石梁退化成纯换算率，没有存量约束。
3. **不用加 `CAP_BASE.stoneBeam`**，改动缩到 `RESS` / `state.res` / `state.got` 三处 + `UNIT` 表
   （`UNIT` 漏了界面就是裸数字）。

### 2.4 「工艺制作效率 +5%」落在哪个数上

- **① 多出货**：造 100 石梁原本吃 100 石头，效率 +5% 后只要 95 石头。
- **② 少出货**：95 石头也能造出 100 石梁。
两者速率完全等价，差别只在界面显示哪个数。⚠️ **待你拍。**

## 三、奇观栏目 & 海潮方碑

### 3.1 与「破冰祭坛」的界线

| | 破冰祭坛 `miracle` | 新栏目「奇观」 |
|---|---|---|
| 性质 | 持续运行的**机器** | 一次性**里程碑建筑** |
| 是否重复 | 可升多级（受 `miracleCap` 约束） | 买断，永久，不重复 |
| 成本 | 持续烧地热 | 一次性资本（石梁为主） |
| 纪元 | 纪元五（`CFG.MIRACLE_ERA = 5`） | 首个纪元一即可（石工解锁） |
| 玩家心智 | 「还在烧吗？」 | 「建成就永远在那儿」 |

⇒ 栏位命名 **奇观**。UI 上要能解释「为什么纪元一到五之间祭坛栏是空的」。

### 3.2 栏位结构

- 每纪元一座，共 5 座，成本递增，全部一次性买断。
- 最后一座指向「破壳」，与祭坛首尾呼应（祭坛是终局削壳引擎，奇观是终局纪念碑）。
- **是否占人口：不占**（已拍）。走纯资本 + 前置科技，跟 `miracle` 的 `unlockScheme` 同一套。

### 3.3 第一座：**海潮方碑**

- **名字**：海潮方碑（已拍）
- **解锁**：石工 `masonry`（`techs.js:248`，纪元一、cost 500、`key: true`、reqs `['quarry']`）。学完即可建。
- **成本**：**石梁为主** —— 用户口径「石梁暂时给海潮方碑做材料，以后给更多建筑」。
  草案 **石梁 20 + 珊瑚 300**（1 石梁 = 100 石头 ⇒ 折合 2000 石头 + 300 珊瑚）。
  ⚠️ 量级待你拍（也可以直接按石头 500 + 珊瑚 300，但那样石梁就没有用武之地了）。
- **效果**（三选一，推荐 C）
  | 方案 | 效果 | 评价 |
  |---|---|---|
  | A | 全产线 +10% | 数值最直白，会变成「买数值」 |
  | B | 所有仓储上限 +50% | 偏防御，前期感知弱 |
  | **C** | **不直接给数值——它「开门」**：建成后开启下一纪元的奇观栏位 | 第一座奇观的价值是**向前**，不是加数字；也解释了栏位为何逐级解锁 |

  推荐 **C + 一条很小的 A**（+3% 全产线），避免「建了没感觉」。⚠️ 待你拍。
