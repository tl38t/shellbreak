# 海洋污染挑战 · 设计规格（DRAFT）

> **状态**：设计草案，未实装。本文档只定义结构与落点，**所有数值均为提议占位、待标定**（用户拍板前不许落进 `config.js`）。
> **范围决策（已定）**：① 挑战专属（不碰基游戏平衡）② 污染 = 存量累积（每秒 += 热液能供给侧×k）③ 通关 = 建戴森球或飞升虚境，按污染阶段评分。
> **纪律回顾**：数值只改 `src/config.js`；改游戏代码前须用户明确同意；标定权在用户。

## 0. 设计目标与一句话总结

给「天壳」加一个**可选挑战**：玩家开启后，所有产出热液能的建筑会持续向海洋排放污染；污染按存量累积、分五个阶段逐级施加 debuff；玩家必须用新设计的净化建筑 / 科技 / 市政 / 奇观把污染压在可控区间，最终在「污染未崩坏」的前提下完成基游戏终局（戴森球 / 飞升虚境）。

核心张力：**热液能是钢、破冰钻机、发射场的命脉，而它恰恰在污染**。越发展越脏，逼迫玩家在「扩张」与「治理」之间做取舍——这正是 Civ6 二氧化碳系统的精髓，但适配成连续 idle tick 的确定性模型。

## 2. 核心模型

### 2.1 状态字段

- `s.pollution`：**净污染存量**（环境里实际残留的污染），`≥0`，初值 0。
- `s.pollutionGross`：**累计排放** = ∫ `hydroSupply` dt（仅用于比例法评分 / 诊断，不参与 debuff）。
- 老档兼容：`migrateRun` 给两个字段补 `0`，缺字段不崩（你纪律里强调过）。

### 2.2 每 tick 结算（概念式，非代码）

```
dP = hydroSupply(s) * k - cleanupRate(s)
s.pollution = max(0, s.pollution + dP * dt)
s.pollutionGross += hydroSupply(s) * dt
```

- `hydroSupply(s)`：复用 `economy.rates(s).hydroSupply`（汽轮机 / 核热厂 / 泰坦气云站 / 太阳帆 / 高压热机管道奇观的供给侧总和，恒 ≥0）。**与 `hydroAlloc` 同源读，不各写一份**（你们的三处同源铁律）。
- `k`：污染系数（提议 **0.1**，待标定）。
- `cleanupRate(s)`：净化站 / 奇观 / 市政提供的每秒扣减量之和。

### 2.3 阶段判定

- **实时面板 / debuff**：按 `s.pollution` 的**绝对阈值**判阶段（即时反馈）。
- **档位评分（推荐比例法）**：按 `s.pollution / s.pollutionGross` 的**比值**判档，自动适配"跑多久、经济多大"，跨局公平。
  - 备选：评分也用绝对阈值（实现更简单，但阈值必须随局长标定，脆弱）。**优先比例法**。

### 2.4 ⚠️ 长局累积标定坑（必须解决）

戴森 / 飞升是终局，整局远长于 8h，后期 `hydroSupply` 轻松上百/s。若 1:1 累积，通关时是千万级，绝对阈值会被瞬间击穿。

- **解法 A（绝对阈值）**：`k` 取极小（如 0.001）+ 净化强，阈值设在十万~千万级。**必须先跑一局挑战 bot 测出 `hydroSupply` 全程剖面才能定**。
- **解法 B（比例法，推荐）**：阶段按「净污染 / 累计排放」比值判，与绝对时长脱钩。实时 debuff 仍用绝对存量给反馈，评分用比值。
- **结论**：实时 debuff 用绝对阈值 + 标定值；档位评分用比例法。比例法的引入使"长局累积"不再是阻塞项。

## 3. 五阶段与 debuff

### 3.1 阶段表（阈值 = 提议占位，待标定）

| 阶段 | 名称 | 主题 | 净污染绝对阈值(提议) | 实时 debuff（提议值，待标定） |
|---|---|---|---|---|
| 0 | 净海 | — | `< 5,000` | 无 |
| 1 | 浊流 | 水质下降 | `5,000 – 20,000` | 幸福度 −1；藻食 −5% |

| 4 | 窒息 | 生态崩塌 | `100,000 – 200,000` | 幸福度 −8；藻食 −40%；全局产出 −25%；人口上限 −30% |
| 5 | 崩坏 | 临界点 | `≥ 200,000` | 阶段4全惩罚 + **污染速率 ×1.5 不可逆加速** |

### 3.2 档位评分（比例法，提议比值，待标定）

| 档位 | 通关瞬间 `pollution / pollutionGross` | 含义 |
|---|---|---|
| 第一档 | `≤ 0.30`（≈ 阶段3 以内） | 勉强达标 |

### 3.3 debuff 接入点（实现前 grep 确认，勿信记忆）

| debuff | 接入函数 / 通道 | 实现形态 |
|---|---|---|
| 幸福度 | `economy` 的 happy 段（喂 `happyMul` 全产档位）；参照 `civics.cardHappyOffset` | 新增 `pollutionHappyOffset(s)` 返回负值，在 happy 段相加 |
| 藻食 | `kelp` 产出乘区（参照 `economy` 的 kelp flow / rates） | 新增 `pollutionKelpMul(s)` 返回 `(1 − 惩罚)`，乘进藻食产出 |
| 全局产出 | `globalMulX(s)` 主乘区（参照 `challenges.productionMul` 的 abyss 钩子） | 新增 `pollutionGlobalMul(s)` 返回 `(1 − 惩罚)`，乘进 `globalMulX` |
| 人口上限 | `popCap`（参照 `1 + lvl.nest*2 + lvl.coralhouse*4`） | 新增 `pollutionPopCapMul(s)` 返回 `(1 − 惩罚)`，乘进 `popCap` |
| 速率 ×1.5 | 阶段5 时 `k` 临时 ×1.5（不可逆，落 `s.pollutionRunaway=true`） | 在 2.2 的 `dP` 公式里对 `k` 乘该标志 |

> ⚠️ 四条 debuff 全是你们**既有主通道**，不引入新乘区、不与 `globalMulX` / `happyMul` 打架；但每个接入点实现前必须 grep 现码确认函数签名与读取顺序（你纪律：实现前先证"tick 路会不会读它"）。

## 4. 净化四件套（门控到 `ocean` 挑战）

两条杠杆分工：**科技 / 市政降速率（`k` 侧），建筑 / 奇观降存量（cleanupRate 侧）**——与你们"供给侧 vs 消耗侧"双轴纪律一致。

### 4.1 建筑 · 深海净化站（提议）

- 每级每秒扣净污染存量 `PURIFY_RATE`（提议 **20/s/级**，待标定）。
- **运转耗藻食 / 金属**（不耗热液能 → 避免"清理自污染"反馈爆炸）；耗料走独立 draw，与 `hydroAlloc` 同式但独立一条。
- 解锁门控：`unlock: { challenge: 'ocean' }`（新增谓词，见 §6.2）。

### 4.2 科技 · 清洁热液（提议）

- 效果：把系数 `k` 从基准降到约 `0.04`（更绿汽轮机 = Civ6 可再生替换化石的等价物）。
- 落点：`CFG.POLLUTE_K` 基准 × `(1 − techReduction)`；或新增 mul 键 `polluteKMul`。

### 4.3 市政 · 排放管制（提议）

- 效果：被动降低污染速率 或 提升净化效率（政策卡或政体效果）。
- 落点：复用 `civics` 现成字段（`card*` / `gov*` 通道），新增 `polluteRateMul` / `purifyBoostMul` 一类键。

### 4.4 奇观 · 蓝碳林 / 深海净化矩阵（提议）

- 效果：大额被动清理（cleanupRate 加一项）或把增速封顶。
- 落点：复用 `wonder.js` 既有 `effect` 出口（如 `hydroBonus` 同款聚合通道），不散读 `s.wonders`。

## 7. 回归断言清单（e2e 须补）

- 挑战激活时 `s.pollution` 初值 0；`hydroSupply>0` 时污染每 tick 增长，不跨 tick 负增长。
- 阶段切换在阈值边界正确（上下边界各一条）。
- 深海净化站确实扣 `s.pollution`（且正确扣藻食 / 金属运转耗）。
- 科技「清洁热液」降低 `k`（污染增速下降）。
- 市政「排放管制」/ 奇观「蓝碳林」生效（cleanupRate 上升）。
- 阶段5 runaway：`s.pollutionRunaway=true` 后 `k×1.5` 不可逆。
- 老档（无 `pollution` 字段）`migrateRun` 补 0，不崩、不 NaN。
- 通关时按 `pollution/pollutionGross` 比值给对应档；超档清零。
- **基游戏（未激活 `ocean`）**：`s.pollution` 恒 0、面板不渲染、净化建筑不可建、无 debuff。

## 8. 风险与开放问题

1. **长局标定**：绝对阈值 vs 比例法已给出方案，但 `k`、各 debuff 量、净化速率的**真实数值**必须等一局挑战 bot 跑出 `hydroSupply` 剖面后才能定（§2.4）。
2. **终局字段名**：戴森球 / 飞升虚境的确切判据字段待 grep 确认（§5.2）。
3. **面板位置**：放自然环境卡还是独立 pane，影响布局与每帧刷新签名（§6）。
4. **净化耗料选择**：藻食 / 金属的组合与量级需标定，确保"清理不自污染"且不构成新瓶颈（§4.1）。
5. **档位比值阈值**：§3.2 的 0.30 / 0.15 / 0.05 是拍的占位，需按"合理清理 vs 放任"两档 bot 实测反推。
