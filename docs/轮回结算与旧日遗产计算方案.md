# 轮回结算与旧日遗产计算方案

> 给 Workbuddy 的规则稿。此文档定义每周目结算时如何产生轮回点、旧日遗迹观光点、旧日艺术品、旧日潮纹碑石与旧日信仰，并提出轮回商店商品目录。商店价格是首轮设计值，接入真实结算后仍需按实跑进度校准。

## 设计目标

- 完成本局 Era 2《神学》后，玩家可以在尚未真正破开天壳时选择轮回；轮回点让前几周目有进展，但单靠重置几次不能直接完成破壳。
- 人口和建筑共同决定轮回点。人口代表文明规模；高纪元建筑代表跨时代建设能力。
- 奇观、艺术品、潮纹记录分别进入不同遗产账本，不能重复折成轮回点。
- 结算只读取本局最终状态，一次结算只发一次；购买、消耗掉的本局物资不会凭空返还。

## 结算资格与时点

### 资格门

资格门就是现有 Era 2 市政 **《神学》**，每一局用 `s.civics.theology`（真值判定，即存档中该市政存在且非零）判定。注意：代码中《神学》完成后存的是 `s.civics.theology = 1`（整数），不是布尔 `true`；判据必须用真值判断（如 `if (s.civics.theology)`），误用 `=== true` 会因严格相等失败而让资格门永远关闭、轮回全盘不触发。代码中《神学》位于 `src/civics.js` 的 Era 2、layer 4，成本 600，完成后开放信仰资源、神庙和相关政策卡；不要误用 Era 4 的《归正会》（`s.civics.reformed`），它是另一项后期市政，只负责解锁“神权政体”。

此门槛按“本局”判定：每一周目都要再次完成《神学》。不要求填写宗教名、不要求 `meta.religionSeen` 已经置位，也不要求后续完成《归正会》或采用神权政体。

### 结算时点

- 玩家在达到资格门后，可在“轮回”确认面板选择开始下一周目；不要求 `s.broken === true`，也不要求壳厚归零。
- 未达到资格门时，重开只按普通重开处理：所有本方案的轮回点和旧日遗产收入均为 0。
- 达到资格门时，确认开始下一周目前结算一次并写入跨周目账本，然后清空周目内资产。
- 第一次合格轮回后解锁轮回商店。
- 破壳本身仍是独立阶段目标；在本局破壳会提高本局轮回点，但不能替代科技、市政或人口建设。

## 轮回点

### 输入量

- `P = s.peak`：本局峰值人口，不用结算瞬间人口，避免冻死或饥荒反向惩罚已达到的人口。
- `L_i = s.lvl[buildingId]`：每种建筑的本局最终等级。
- `e_i`：建筑的起始解锁纪元。建筑表新增显式 `metaEra` 字段；按最早可建的科技/市政归属，不随玩家当前科技纪元改变。后续新增建筑必须填写此字段。
- `q = clamp(1 - s.shell / s.iceShell, 0, 1)`：本局破壳进度。若完整破开天壳，`q = 1`；完全没有削壳时 `q = 0`。

纪元权重：

| 建筑/奇观纪元 | 权重 `W[e]` |
|---|---:|
| Era 1 暗流纪 | 1 |
| Era 2 冷焰纪 | 2 |
| Era 3 硫泉纪 | 3 |
| Era 4 洋流纪 | 5 |
| Era 5 破壳纪 | 8 |

### 公式

先算文明发展分：

```text
populationScore = 2 × P
buildingScore   = Σ_i W[e_i] × log2(1 + L_i)
craftScore      = CRAFT_W × 已解锁工坊项目数
                 （已解锁配方 + 已购买工具 + 已装填升级，各计 1 项）
developmentScore = populationScore + buildingScore + craftScore
shellFactor = 0.5 + 0.5 × q

earnedTide = 1 + floor(developmentScore × TIDE.LINEAR_K × shellFactor)
```

规则：

- 已完成《神学》时至少获得 1 点；资格门未达到时为 0。
- **线性映射（2026-10-05 改）**：最终点数对发展分线性，不再用平方根——平方根会把后期努力压缩得几乎无感，导致「好局和烂局差不大」。系数 `TIDE.LINEAR_K`（现 0.04）由 config 集中管理，便于标定。
- 人口按线性计入，建筑等级按 `log2(1 + level)` 递减计入，避免单一低阶建筑无限堆级压过人口和高纪元建设。
- 高纪元建筑权重更高；建筑的纪元按 `metaEra` 固定，不根据解锁后的当前纪元回溯改价。
- **工坊解锁项（2026-10-05 加）**：玩家实际开通的工坊内容（配方/工具/升级）每项按 `TIDE.CRAFT_W`（现 4）计入发展分，让「开工坊线」也贡献周目收益。配方以 need/needCivic 门满足视为解锁（不看材料是否够）；工具/升级以 `s.tools`/`s.upgrades` 已置位视为拿到手。
- 破壳进度把公式结果从 50% 提升到 100%。因此，未破壳的早期轮回能积累少量轮回点；真正破壳的周目回报更高。
- 轮回点向下取整；不设人为最高上限。

示例（数值用于说明公式，`LINEAR_K=0.04`、`CRAFT_W=4`，不代表固定通关配置）：

| 本局概况 | `developmentScore` | `q` | 获得轮回点 |
|---|---:|---:|---:|
| 刚到资格门，`P=25`，建筑分 20，工坊 6 项，破壳进度 10% | 96 | 0.10 | 2 |
| 中期轮回，`P=70`，建筑分 80，工坊 12 项，破壳进度 50% | 268 | 0.50 | 6 |
| 高发展并破壳，`P=100`，建筑分 150，工坊 16 项，壳已破 | 474 | 1.00 | 20 |

## 旧日遗迹观光点

旧日观光点代表奇观首次进入跨周目“遗迹名录”。每座独特奇观在账号存续期间只入藏一次，不按纪元加权：

```text
newlyMemorialized = { w.id | s.wonders[w.id] === true && !meta.memorialWonders[w.id] }
earnedRelicTourism = count(newlyMemorialized)
meta.memorialWonders = union(meta.memorialWonders, newlyMemorialized)
relicWonderCount = count(meta.memorialWonders)  // 更新后计数
relicScienceMul = 1 + 0.01 × relicWonderCount
relicCultureMul = 1 + 0.01 × relicWonderCount
```

- 结算时检查本局 `s.wonders` 与账号级 `meta.memorialWonders`。每个首次出现的 `w.id` 入藏，增加 1 旧日观光点，并在 `memorialWonders[w.id]` 中永久登记。
- 每座已入藏奇观永久给科技点获取 +1%、市政点获取 +1%。N 座独特奇观即两项各 `×(1 + 0.01N)`；这是加算百分比乘区，不对每座奇观连乘 `1.01^N`。
- 同一奇观以后周目再次建成，既不再发观光点，也不再重复加百分比。新奇观首次建成才增加一档。
- 只在达到本局《神学》资格门并确认轮回时登记；普通重开不入藏、不发点。
- 例如首次轮回时本局有 4 座此前未入藏的奇观：获得 4 观光点，永久科技与市政获取各 +4%。后续周目重复建这 4 座，奖励为 0；再首次建成 1 座新奇观，则额外获得 1 点、两项各 +1%。
- 每座首次入藏奇观同时记为 1 个旧日观光点；观光点是永久纪念计数，不可消费。科技/市政加成按已入藏独特奇观数量计算。

## 旧日艺术品

《历史哲学》配方产出的 `artwork` 是本局可消耗工艺资源。合格轮回时，把结算时还持有的完整件数转成旧日艺术品：

```text
earnedOldArtwork = floor(max(0, s.res.artwork))
```

- 只转结算时库存；已经投入其他用途或不存在于库存中的艺术品不计。
- 小数尾数不转入遗产账本，避免工艺效率乘区生成碎片后绕过整件成本。
- 每件旧日艺术品同时永久增加市政点速度，采用**绝对数值加法**和递减边际收益：

```text
H(n) = Σ(k=1..n) 1/k
oldArtworkCultureRate = 0.15 × H(oldArtworkEarnedTotal)  // 市政点/秒
```

- 每新获得第 `n` 件，永久增加 `0.15 / n` 市政点/秒：第 1 件 +0.15/s、第 2 件 +0.075/s、第 3 件 +0.05/s、第 4 件 +0.0375/s、第 5 件 +0.03/s、第 10 件 +0.015/s。
- 0.15/s 对齐当前 `UNIT.culture`，即一件的首档加成相当于一名未加成书手的基础产出。总加成缓慢增长、没有百分比乘区，也没有硬上限。
- 速度加成按账号累计获得总数计算。旧日艺术品是永久遗产计数，不可消费；商店不读取其数量作为价格。

## 旧日潮纹碑石

现有配方资源 `tidalRecord` 结算时映射为旧日潮纹碑石。合格轮回时：

```text
earnedOldTideSteles = floor(max(0, s.res.tidalRecord))
```

- 只计结算时仍持有的完整件数；已消耗或小数尾数不计。
- 每件潮纹记录对应 1 块旧日潮纹碑石，不再乘纪元权重。它的高成本（科技 5000 + 钢制零件 10）已经体现稀缺度。
- 每块旧日潮纹碑石同时永久增加科技点速度，沿用同一递减曲线：

```text
oldTideSteleScienceRate = 0.15 × H(oldTideStelesEarnedTotal)  // 科技点/秒
```

- 每新获得第 `n` 块，永久增加 `0.15 / n` 科技点/秒；前 1、2、3、4、5、10 块的边际值依次为 +0.15、+0.075、+0.05、+0.0375、+0.03、+0.015 科技点/秒。
- 0.15/s 对齐当前 `UNIT.sci`，即首块相当于一名未加成学者的基础产出。此加成是固定科技点/秒，不是科技产出的百分比。
- 速度加成按账号累计获得总数计算。旧日潮纹碑石是永久遗产计数，不可消费；商店不读取其数量作为价格。
- 未达资格门的普通重开不转化。

### 固定产出加成的接入规则

- 两项收益都是最终产出上的固定加项：在市政点/科技点已有建筑、科技、市政、政策卡、奇观、全产倍率都算完之后，再分别加上上述每秒数值。
- 加项本身不再吃 `globalMul`、政策卡乘区、建筑乘区或奇观乘区；这样每件文物提供的数值始终可预测，不会随其他乘区滚雪球。
- 旧日遗迹对科技/市政的 +1%/座则是独立的总获取乘区；先按现有规则算出科技/市政总产出，再乘 `1 + 0.01 × 已入藏独特奇观数`。观光点计数与入藏 ID 一致，不进入商店余额。
- 游戏 tick 实际入账与 `rates()` 面板预览必须共用同一加项，dt=1 时两者相等。

## 旧日信仰（沿用已确认的方案）

本局剩余信仰在合格轮回时并入跨周目的 `oldFaith` 总量：

```text
meta.oldFaith += max(0, s.res.faith)
faithTier = max(0, floor(log10(meta.oldFaith)))
oldFaithAllProductionBonus = 0.005 × faithTier
```

- 对数档位：旧日信仰累计量到 10 / 100 / 1,000 / 10,000 时，全产分别 +0.5% / +1.0% / +1.5% / +2.0%。低于 10 时为 +0%。
- 该加成作用于全产乘区；信仰自身基础产出不得吃自己的全产加成，避免正反馈。
- 旧日信仰独立于轮回点和三类旧日遗产；不消耗、不兑换。
- 浮点边界计算 `floor(log10(value) + 1e-9)`；`value <= 0` 时档位为 0。

## 跨周目账本与防重复结算

建议在 `meta` 增加以下累计字段，旧档迁移默认补 0：

```js
{
  oldFaith: 0,
  oldRelicTourism: 0, // 永久观光计数，不可消费；等于已入藏独特奇观数
  memorialWonders: {},
  oldArtworkEarnedTotal: 0,
  oldTideStelesEarnedTotal: 0,
  // oldArtworkEarnedTotal / oldTideStelesEarnedTotal 是永久遗产计数，不可消费。
  // tide 沿用唯一可消费的轮回点余额；spent 沿用累计消费字段。
}
```

合格轮回结算时按以下顺序处理：

1. 计算本次 `earnedTide`、首次入藏奇观集合、`earnedOldArtwork`、`earnedOldTideSteles` 和本局剩余 `faith`。
2. 把新奇观 ID 加入 `meta.memorialWonders`，并按集合大小更新永久科技/市政获取乘区。
3. 将本次轮回点加到唯一可消费的 `meta.tide`；观光点、旧艺术品、碑石只累加到永久遗产计数。
4. 把本周目标记为已结算，再启动新周目；重复调用不得重复入账。
5. 结算面板列出轮回点的“本次获得 / 可用余额”，并列出观光点、艺术品和碑石的“本次获得 / 永久累计”；显示首次入藏奇观名与由此新增的科研、市政百分比；未达资格门时本次奖励为 0。

`meta.tide` 是商店唯一可消费余额。`meta.oldRelicTourism` 是永久观光计数，等于 `memorialWonders` 中已入藏的独特奇观数；其数值专供展示，奇观 ID 集合专供 +1%/座加成读取。`oldArtworkEarnedTotal` 与 `oldTideStelesEarnedTotal` 分别记录永久艺术品/碑石累计数，专供固定速度加成读取。旧存档若含 `oldArtwork` / `oldTideSteles` 余额字段，迁移时并入相应累计数后停止把它们当作货币。

## 对现有实现的替换范围

现有 `src/prestige.js` 是旧方案：用 `POP_GATE / POP_SLOPE / POP_ESC / LAYER / B_W` 计算轮回点，且 `doBreak()` 以破冰为结算入口、以 `meta.religionSeen` 决定发点。实现本稿时应整体替换这套“破冰后才结算”的收益判据，避免把旧公式再叠加一次：

- 新资格门：本局完成 `s.civics.theology`（Era 2《神学》）。不可用 Era 4 的 `s.civics.reformed` 替代。
- 新结算入口：合格后玩家主动选择“开始轮回”；结算时不要求壳已破。
- 新点数：只用本稿 `developmentScore` 与 `shellFactor` 公式；旧 `POP_GATE` 等字段不再参与。
- `s.broken` 仍用于真正破壳的游戏状态、成就和阶段结果，不再是获得跨周目收益的必要条件。
- 当前只有“破壳后结算”流程；需要让重开/轮回确认入口在资格达成后改走本结算，并保留未达资格前的普通重开行为。
- 保留 `religionSeen` 的宗教命名/叙事用途，不把它当作本局资格门或本次是否发遗产的依据；神学完成本身即可满足资格。

## 轮回商店商品提案

### 商店规则

- 首次完成合格轮回后开放；所有购买项写入账号级 `meta`，之后每局自动生效。
- 轮回点是商店唯一货币：所有解锁、等级和便利功能都消耗轮回点。旧日观光点、旧日艺术品、旧日潮纹碑石只提供此前确认的永久加成和累计展示，不进入商店。旧日信仰不可花，继续只按对数曲线提供全产加成。
- 永久商品可以分级购买；购买后不退款。购买等级与轮回点余额分开存。奇观、艺术品、碑石的加成分别根据入藏数量或累计获得总数计算，商店购买不会减少这些永久收益。分级商品采用独立逐级定价：价目表中的 `3 / 6 / 12` 等即为各单级标价（不累计），购买第 k 级时单独扣除该级标价 `PRICE[k]`，且须逐级购买、不能跳级；购买后 `meta.perks[id]` 等级 +1 并扣减 `meta.tide`。
- 商品效果以不跳过本局科技、市政、职业、资源和奇观解锁链为边界。商店加速重复劳动，不直接赠送高纪元建筑、科技完成或奇观完成。
- 下表价格是可先接线的起始报价，不是已经模拟平衡的终值。结算系统接好后，用真实策略实跑每次轮回的收入与购买时间，再调价格；不通过测试夹具或离线假定收入改价。

### 代码现况与覆盖范围

商店商品围绕已经存在的循环设计，而不是只在资源面板加几条百分比：

| 游戏循环 | 代码里的实际内容 | 商店应该帮助什么 |
|---|---|---|
| 人口与住房 | 族民由生存、口粮和住房共同限制；住房含礁口巢、石屋、廉租社区 | 起始住房余量、住房效率、配工方案；不能直接给大量人口 |
| 职业与资源 | 采集者、珊瑚匠、采石工、矿工、匠人、学者、书手、官员、商人各自产资源 | 保存/恢复配工比例，缓解重开后重复配人 |
| 资源与仓储 | 藻食、珊瑚、石头、金属、暖石、精铁、热液能、钢、钛等；有限仓储靠仓库升级和灯塔 | 开局小包、有限资源仓储、采集/生产效率；不发放跨时代稀有资源 |
| 工坊 | 石梁、硬化珊瑚、铁制支架、绳、钢制零件、脚手架、共振钻头、艺术品、潮纹记录等反复配方；青铜/铁/钢工具和工艺升级需逐项购买 | 自动制作槽、配方模板、工坊采购清单；不替玩家跨科技门槛造料 |

### 放置游戏参照与取舍

- 《猫国建设者》将 Karma 与 Paragon 作为不同的重置收益；后期时间系统还允许通过 Chronosphere 携带部分资源，并用 Cryochamber 携带族民。借鉴点是把“永久成长”和“本局携带”分开、让携带能力成为昂贵且有门槛的系统。本作先不直接继承人口或整仓资源，避免跳过每局的生存/采集/住房链。[资源说明](https://wiki.kittensgame.com/en/general-information/resources)、[Time 系统](https://wiki.kittensgame.com/s/en/game-tabs/time)
- 《Trimps》的 Portal 将本局重置与长期 Perks、Heirlooms、挑战奖励等保留项分层；不同挑战还能逐步开放长期便利。借鉴点是商店除了倍率，也应有分阶段解锁的便利与玩法工具。[Portal 说明](https://trimps.fandom.com/wiki/Portal)
- 《Antimatter Dimensions》的 Reality Perks 主要提供便利与自动化，Automator 则是后续解锁的脚本工具。借鉴点是自动化本身可以作为长期购买目标，但应该先解锁、默认由玩家配置，并保留明确的开关/停止条件。本作因此用有限的自动制作槽和方案模板，先解决重复劳动，不做一个开局替玩家全自动通关的黑箱。[Reality 说明](https://antimatterdimensions.wiki.gg/wiki/Reality)

归纳成三条商店原则：永久倍率、一次性/每局资源、操作自动化要分开；自动化先按具体任务解锁且可关；重置后保存的是工具、配方与方案，不直接保存本局发展成果。

### 乘区、读取和结算约定

- `relicWonderCount = count(meta.memorialWonders)`；`shopCivicBonus = 0.02 × civicArchiveLevel`；`shopScienceBonus = 0.02 × tideProofLevel`。
- 人口上限：`houseBase + 原有住房容量 + 广厦之基等级 + 生息建筑规划等级 × 所有人口建筑等级总和`。生息建筑规划为买断项，等级为 0 或 1；每个当前提供人口上限的建筑等级（礁口巢、石屋、廉租社区）额外提供 1 人口位。
- 市政最终产出：`(本局现有市政点产出 + 旧日艺术品固定市政点/秒) × relicCultureMul × (1 + shopCivicBonus)`。
- 科技最终产出：`(本局现有科技点产出 + 旧日潮纹碑石固定科技点/秒) × relicScienceMul × (1 + shopScienceBonus)`。
- `relicCultureMul` / `relicScienceMul` 仍为 `1 + 0.01 × relicWonderCount`。遗迹乘区、市政商店乘区、科研商店乘区分别读取一次；不把同一乘区拆成逐件连乘。
- 寒潮储备只改寒季资源产出系数：`coldSeasonMul = baseColdSeasonMul + 0.02 × coldStoreLevel`；寒壳护佑只改冻伤概率：`freezeChanceAfterLegacy = freezeChanceBeforeLegacy × 0.95^coldWardLevel`。两项都不更改基础天气表、暖石效果或冰封期门槛。
- 材料总仓只放大 `CAP_BASE` 中有明确容量的资源；`science`、`culture`、`faith`、`luxury` 和无上限工艺品不在范围内。若资源没有仓储上限，不得因为新商店而人为加上限。
- 旧学开篇每局只发最高已购档对应的起始科技点，不能把 I、II、III 三档重复相加。
- 政令档案、生计名册和工坊采购单都是存档模板/按钮便利；每局重开时提示玩家确认套用。科技/市政自动研究和分区自动建造是独立解锁的后台执行器，但每局默认关闭且可暂停。
- 奇观建造折扣用 `1 - 0.05 × wonderBlueprintLevel`，最高等级 4。广厦之基的等级范围是 0–3，生息建筑规划是 0–1；所有商店购买等级统一写入账号级 `meta.perks`，只消耗轮回点，并在 `freshRun` 后继续生效。
- 破界测绘用 `1 + 0.05 × shellSurveyLevel` 乘在破冰祭坛的削壳率上，最高等级 3；不乘在消耗上。
- 自动制作槽数写入账号存档；槽位中的配方选择与目标存量可保存为跨周目模板，但新周目默认不运行，须玩家确认启动，避免开局自动消耗资源或把配方链顺序打乱。
- 轮回前遗产制作永久解锁后，艺术品与潮纹记录自动制作开关每局分别默认关闭；轮回确认前展示预计消耗的市政点/科技点、绳/钢制零件和预计遗产件数。确认轮回时按现有 MAX 制作逻辑先制作，再按本方案的 `floor` 规则结算库存。

旧日观光点、艺术品、碑石和信仰只按先前讨论提供永久遗产效果；它们都不消费。轮回点是唯一商店货币，分支覆盖开局便利、自动化、奇观/破壳、市政/政策与科技。价格与收益均待接入真实轮回结算后的实跑校准。

### 建议的落地顺序

1. **轮回基础**：资格门、结算、存档迁移、唯一可消费的轮回点账本，以及只累积不消费的观光点/艺术品/碑石/信仰规则；先确保每次奖励与记录正确。
2. **第一批商店**：现有轮回点加成、广厦之基/生息建筑规划、观光点/艺术品/碑石原本对应的所有商店效果改为轮回点解锁、奇观折扣、破界测绘。
3. **减少重复操作**：自动制作槽、科技自动研究、市政自动研究、工坊采购单、生计名册和政令档案；自动化默认关闭，方案恢复须玩家确认。
4. **舒适度商品**：离潮计时、材料总仓、寒潮储备、寒壳护佑，以及分区自动建造许可。
5. **以后再评估**：奢侈品贸易消费、信仰局内消费、燃料资源去向和进入宇宙后的新周目层级。等这些玩法有正式消耗/进度目标后再为它们单开商店分支，不预支尚未设计的系统。

前两批是新轮回循环的骨架；第三批是降低重复劳动的主目标；第四批商品偏便利，允许分版本上线。平衡时同时记录每个商品的“最早可买周目、累计花费周目数、缩短的重复操作/游戏时间、是否令 Era 2《神学》资格门过快”，不要只比较价格数字。
