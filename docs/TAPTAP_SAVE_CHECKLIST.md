## 每次验完要看的三处

1. **存档管理面板底部**一行健康度（上次保存 / ⚠ 错误）
2. **「复制诊断信息」**（面板按钮）—— 里面这几项是判据：
   | 字段 | 含义 | 正常长什么样 |
   |---|---|---|
   | `cap` | 能力位 `ls/ts/fs/cl` | TapTap 里应为 `ls1ts1fs1cl1` |
   | `boot` | 本次启动从哪来 | `resumed:localStorage` / `resumed:native:a` / `resumed:native:hide` / `new` |
   | `boots` | 累计启动次数 | 每次重进 +1（=1 说明诊断没写进去） |
   | `ok/f/s` | 写盘成功 / 失败 / 拒写 | `f=0 s=0`；有 `s` 说明某资源出现过 NaN |
   | `rb` | 读回 一致/空/不一致 | `不一致=0` |
   | `lost/em` | 丢档次数 / 尸检副本 | 正常 `lost=0`；非 0 说明本机曾经读不到档 |
   | `err` | 最近一次错误 | 空 |
3. **面板顶部「本地 / 云端」对比块**（周目 · 时长 · 时间）

## 五条路径

### ① 关闭重进（正常关闭）
- 玩 1 分钟 → 从后台任务栏**划掉**游戏 → 重进
- 期望：进度**没有**回退；`boot=resumed:localStorage`；`boots` +1；`err` 空
- 若 `boot=new`：本机三处与云端都没读到 —— 直接把诊断文本发我

### ② 后台杀进程（onHide 那条）
- 玩 1 分钟 → **返回桌面**（不划掉）→ 等 30 秒 → 从最近任务里划掉 → 重进
- 期望：进度末尾那段（切后台前的最后几秒）**还在**
- 判据：重进后 `boot` 可能是 `resumed:native:hide`（这份就是 onHide 写的同步快照）
- 若 `err` 出现「后台原生文件同步保存未确认」⇒ 同步写被拒，把诊断发我

### ③ 弱网启动
- 开启飞行模式（或限速到 50KB/s）→ 杀进程 → 重进
- 期望：**能进游戏**（本机有档时应直接恢复，压根不该去问云端）
- 若看到「为保护旧档，已暂停开新局」：那是**本机也没读到**才该出现的结果。
  此时点「重新检查存档」；网络恢复后应能恢复。把这条截图发我 —— 它说明本机读取也超时了
- ⚠️ 绝对不该出现：进度变成 0.0x 小时的新局

### ④ 版本更新（模拟「清缓存 / 重装」）
- 系统设置里清掉游戏数据（或卸载重装，若 TapTap 侧允许）→ 重进
- 期望：`boot=resumed:native:a` 或 `:b`，进度回来
- 若变成新局：`lost` 会 +1 且出现尸检副本按钮「导出旧档副本」，直接导出那份发我

### ⑤ 轮回后重进
- 打一次轮回（或先在存档面板手动上传一次云存档）→ 轮回 → 玩 3 分钟 → 重进
- 期望：**自动云备份继续工作**（面板顶部云端时间会更新）
- 重点判据：**不该**出现「云端存档较新，已停止自动覆盖」
  （旧版按本周目时长比较，轮回后必然误判 ⇒ 自动备份永久停摆，这次就是修它）
- 云端会看到**两槽**：`shellbreak_main` 与 `shellbreak_previous`，
  这是刻意的「保留上一版本」，不是重复上传

## 出问题时发回什么

诊断文本（面板「复制诊断信息」）+ 当时的面板截图 + 「第几条路径 + 做了什么」。
有 `boot` 与 `cap` 这两行，绝大多数情况能直接定位到是哪一环断的。
