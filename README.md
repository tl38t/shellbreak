# 天壳 · SHELLBREAK

> 文明越大，壳越薄。在冰壳把你冻死之前凿穿它。

一期范围：**原始时代 → 破冰重置**。大气壳、星海、贸易、深渊低语留到二期。

## 运行

双击 `index.html`。纯前端，无构建、无依赖、无联网。
首次进入会写 localStorage 存档（跨周目的洋流点与当前周目进度）。

## 玩法骨架

| 阶段 | 你要做的事 | 天壳 |
|---|---|---|
| 开局 | **只有浮游藻田能建**。攒珊瑚，其它建筑逐扇露头 | 破壳系数随人口/级数/科技上涨，自动削壳 |
| 铺基建 | 解锁链：工坊（珊瑚→骨材）→ 珊瑚巢 → 熔炉/聆听巢 → 热泉井 → 祭坛 | 每多一级建筑，系数就多一点 |
| 过冬 | 暖/平/浊/寒四季轮转，寒流季产出 ×0.25 | 自动削壳持续到 25% 下限就停手 |
| 冰封期 | 全局产出 ×0.6，族民会冻死；取暖石与热力学降低冻伤 | 壳停在 25%，自动削壳到此为止 |
| 凿穿 | 建热泉井供地热、建破冰祭坛合闸；**地热见底祭坛自动停摆** | 祭坛是凿穿最后 25% 的唯一手段 |
| 破冰 | 壳归零 → 结算洋流点 → 下一周目 | — |
| 周目 | 用洋流点买增益：起始资源 / 产出效率 / 门槛减免 | 冰壳更薄、采集更快 |

**洋流点只认峰值族民**：破冰时人口没过 35，这一局剥出的洋流点是 0。过线之后每 1 人 36 分，
150 人以上那段再抬到 54 分。建筑存量只按 2% 折算——所以这局有两条主线，一条是凿壳，
一条是**养人口**，而第二条才是重置收益的来源。这条对齐猫国建设者源码里那两行
（`kittens > 35` 才有 karma、`> 70` 才有 paragon）：它的第一阶段目标不是「打通什么」，
是「养出多少人」。

核心张力：**自动削壳只会把你带到 25%，凿穿最后那段要烧地热，而地热抢的是匠人**。
调人去当匠人，产出降、采集慢；调人去采集，祭坛就停摆。两种打法实测
rational 10.65h / rush 9.80h 破冰，不供燃料则永远卡在 25%——这是设计里的硬门，不是装饰。

### 解锁链（照抄猫国建设者的四种机制）

建筑没有等级上限，也不会一开始就全列出来。四种解锁条件在 `src/habitat.js: unlocked()` 里并存：

| 字段 | 含义 | 本作用在 |
|---|---|---|
| `defaultUnlockable` | 永远可建 | 只有 `kelp` 浮游藻田 |
| `unlockRatio` | 库存达到首级价格的这个比例才露头（猫国默认 0.3） | 工坊 / 礁石 / 砂矿 / 取暖石 |
| `unlockScheme` | 某资源持有量达阈值才解锁 | 珊瑚巢需骨材 60；热泉井需精铁 60；祭坛需精铁 300 |
| `requiredTech` | 必须已研究某科技 | 熔炉需冶炼术；聆听巢需历法 |

**默认锁着**：没声明任何解锁条件的建筑不会出现。猫国的 `unlockable` 在官方 Spec 里标为
MANDATORY（必填），本作同理——漏写等于「忘了决定」，不该默认摊开给玩家。

成本递增系数也是**每建筑自己的** `ratio`（猫国 `priceRatio`，同样是 Spec 必填），
没有全局统一值：藻田 1.12 便宜到可以一路铺开，珊瑚巢 2.50 贵到买不动。
**住房没有硬上限，人口靠珊瑚巢的 2.5 倍成本自然封顶**——和猫国压住房价的手段是同一个。

## 回归验证


当前基线：

| 指标 | 值 |
|---|---|
| rational 策略破冰 | 10.65 h（基础削壳 67% / 祭坛 33%），峰值 54 人 → 洋流点 6.52 |
| rush 策略破冰 | 9.80 h（峰值 48 人 → 5.68） |

## 定稿数值（src/config.js）

| 项 | 值 |
|---|---|
| 冰封壳总厚 ICE_SHELL | 200000 |
| 冰封阈值 / 自动削壳下限 | 0.25 / 0.25 |
| 破壳系数 | `0.26·pop^0.62 + 0.14·lvl^0.72 + 0.80·科技数 + 1.30·祭坛级`（冰封期 ×1.35） |
| 自动削壳速率 | `0.40 × 系数` 点/秒，只削到 25% 停手 |
| 祭坛削壳 | `1.10 × 祭坛级` 点/秒；耗地热 `0.55 × 级 ×(1+0.35×(级−1))`/秒 |
| 地热产出 | `热泉井级 × 0.010 × 匠人数 × 环境系数 ×(点火术 1.4)` |
| 建筑成本 | `ceil(基数 × ratio^当前级)`，ratio 每建筑不同（藻田 1.12 / 珊瑚巢 2.50 / 其余 1.15） |
| 仓储 | `CAP_BASE + 建筑总级 × 400`，超限部分浪费 |
| 口粮 | 每人每秒 0.06；藻田 +0.55/级/秒 |
| 季节 | 暖 1.5 / 平 1.0 / 浊 1.0 / 寒 0.25，每季 6000 秒 |
| 破冰结算 | 峰值族民 ≤35 发 **0 点**；否则 `shellScore = 200×层数 + 36×(P−35) + 54×(P−150,若过) + 0.02×B分段`，`tide = (√(1+8·score/40)−1)/2` |

标定是扫出来的，不是拍出来的。三条实测结论写在这里，改数值前先看：
- **产能对时长几乎无影响**（产出 ×10，时长只从 9.5h 变 9.0h）。所以别靠"调产出"改节奏。
- **成本曲线是「长度」不是「难度」**（冰壳 300k→180k，时长 14.66h→9.86h，线性）。
  想改节奏先动 `ICE_SHELL`。
- **真正决定时长的是系数与燃料**：系数 ÷10 → 时长明显变长；燃料收紧 → 末段从"干等"变成"资源战"。
- **重置收益要锚在人口上，不是建筑级**：锚错时会表现为三档策略洋流点几乎一样
  （15.40 / 14.82 / 15.73），玩家这一局打得好不好在重置时完全感觉不到。
  `balance.mjs` 里有两条断言盯着这事，改公式别把它们摘掉。

## 开发中修掉的坑（写代码时别再踩）

1. **`broken` 的置位权只属于 `prestige.doBreak`**：`shell.js` 在调用它之前先写了
   `s.broken = true`，于是 `doBreak` 开头的「已结算则返回」守卫直接 return，
   **结算面板与洋流点全部丢失**。这类「两个地方都能置同一个标志位」的写法，谁先写谁堵死另一条路。
2. **事件委托里不能直接把当前状态传回去**：`toggleMiracle(s.miracleOn)` 等价于
   「把它设成它现在的值」，复选框永远打不开。click 时刻 `checked` 还是旧值，必须取反求目标态。
3. **建不起的建筑必须从建造队列里跳过**：只看「未满级」不看「买得起」，`geyser`（要精铁）
   会永远堵在队首，而精铁只有 `furnace` 能产 —— 整局冻结。缺资源不是跳过，是卡死。
4. **建筑默认锁着，不默认展开**：`unlocked()` 只在建筑声明了 `requiredTech` / `unlockScheme` /
   `unlockRatio` 时才判定具体条件。漏写全部三种 = 永远不出现（比猫国 Spec 的 `unlockable`
   必填更严），而只写 `need` 的建筑会直接躺在开局列表里——祭坛就踩过这个坑。
5. **`ratio` 是每建筑自己的，没有全局 fallback**：`costOf` 直接读 `b.ratio`。
   漏写不会报错，只会变成 `NaN` 成本，建筑永远建不起且毫无提示。
6. **被动削壳下限**：削壳必须夹在下限上，否则后期一级建筑就跳过整个阶段。
7. **前置建筑只写真实存在的建筑 id**：早期误写 `need:'dig'` 而 `lvl` 里没有这个键，建筑永远建不起来。
8. **职业分配差额**：人口在两次决策之间会变，jobs 总和常 ≠ pop。
   必须先消化差额，否则所有职类都低于目标、找不到供体，分配整个空转。
9. **`showBreakPanel` 导出**：`SB.game` 必须导出它，`prestige.doBreak` 会调用。
10. **新周目落盘**：`startRun()` 必须立刻 `saveRun`，否则刷新页面丢进度。
