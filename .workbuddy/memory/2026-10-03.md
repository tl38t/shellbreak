## 「还没研究神学，按钮怎么就是『轮回』了？」—— 根因（2026-10-03 下午）

用户报：实机底栏按钮写「轮回」，但当局没研究神学。

**链路（已逐行核实）**：
1. 底栏按钮文案 = `meta().religionSeen ? '轮回' : '重开本周目'`（`render.js:1330`）。
2. `religionSeen` = 「**建立过**宗教」，**永久跨周目**（`state.js:11-12`）；由 `game.maybeReligionPopup`
   在 `s.religionName` 非空时置真（`game.js:242-246`）。
3. 命名框只在 `s.civics.theology` 时渲染（`render.js:328`），faith 页门也是神学（`game.js:36`
   + `economy.resUnlocked(s,'faith')`）⇒ 全新档不可能跳过神学建立宗教。
4. 但 `s.religionName` 是**周目内**字段（`state.js:215`，freshRun 清空），`religionSeen` 不是。

⇒ **两种情况都能出这个现象**：① 早前某周目建过宗教（新周目神学被重置、按钮仍写轮回，这是
2026-09-29 规格）；② **旧档迁移**（`state.js:272-275`）——缺 `religionSeen` 字段且有跨周目进度的旧档
被自动补 `religionSeen=true; shopUnlocked=true`，**不发弹窗**，玩家毫无印象。

**⚠️ 顺带挖出的真问题**：迁移宽限此刻**必然过度发放**。判据里的 `cycle>1` 在
`fuelRate=0`（破冰不可能发生）时期**只能**来自「重开本周目」软重置，绝不可能是真轮回，
却被判成「早就建立过宗教、也轮回过」⇒ 老档凭空拿到「轮回」按钮 + 打开的轮回商店。
（修法：迁移不再单判 `cycle>1`，或本期内不发双解锁。**未动手，等用户拍**。）

**不受影响**：5.37h（第一次轮回 = 解锁神学 + 命名）测的就是这个翻转点本身，口径无误；
全新档（清空存档后）`religionSeen=false`，按钮确为「重开本周目」。

## 礁口巢首级造价 10→5 珊瑚（同日下午 · 用户确认）

用户问：「礁口巢第一栋建造花费不是改成 5 珊瑚了吗？」—— 核出**源码半吊子不一致**：

- `config.js:1035` 真实造价常数仍是 `cost: {coral: 10}`（游戏真按 10 收）；
- 但游戏内 UI 文案（`render.js:364,534`「攒 5 珊瑚盖起礁口巢」）+ 注释（`techs.js:143`、`config.js:164`
  都说「5」），只有 `economy.js:76` 注释还写「10」（陈旧）。

⇒ 「改 5」只落地了 UI/注释，`config.js` 常数没动；清单（updated3）如实跟 config = 珊瑚 10，所以跟 UI 对不上。

**处置**：用户确认目标值是 5，改 config.js 常数 + 顺手修 economy.js:76 陈旧注释 + 清单 礁口巢行
`珊瑚 10 → 珊瑚 5`，`index.html` `config.js ?v=98→99`。

**⚠️ 连带踩中 e2e 住房比值断言的潜伏 bug**：该断言**名字与通过语早就写「4 倍」**（且通过语明写
「巢 2.50 / 屋 10.00」），但**阈值那行却写 `Math.abs(perHouse/perNest - 2) > 0.1`**（期待 2.0）。
旧版 nest=10 时比值恰=2.0，凑巧过了；nest=5 后比值变 4.0，戳穿错配 → 红。

**修法（更稳）**：期望值从建筑定义**实时推导** `expRatio=(houseBase/4)/(nestBase/2)`（改首级成本时自动跟着变、
不假红）；容差 0.1→**0.2**。原因：costOf 对每级成本 `Math.ceil`，巢基数小（5）时相对误差放大，
**L2 实测比值 3.846（偏离 4.0 达 0.154）**，0.1 不够；硬不变量仍是「石屋每人口永不低于巢」（`perHouse < perNest` 必红）。
各等级实测比值：L1=4.000 / L2=3.846 / L3=3.906 / L4=3.956 / L5=3.987 / L6=3.995 / L7=3.999 / L8=4.000。

**回归**：`node --max-old-space-size=4096 sim/e2e.mjs` → **610/610 全绿**（含此断言）。
**设计后果提示给用户**：nest=5 让「石屋/礁口巢每人口成本比」从 2× 变成 **4×**（石屋相对更贵一档），
属 nest=5 的数学必然；若想保 2× 得同步调低石屋首级成本（用户未要求，未动）。
