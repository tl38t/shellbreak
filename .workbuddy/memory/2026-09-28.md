## 核算前先挖出一个致命 bug（本轮主线）
**`src/economy.js` 的 `capOf` 少一对括号，整条资源线容量恒 0。**（我 09-27 加奇观仓储时写出来的）
```js
return base + (s.lvl.ballast||0)*BLD.ballastCap + SB.wonder ? SB.wonder.matMaxBonus(s,k) : 0;
```
`+` 优先级高于 `?:` ⇒ 左半边整个变成条件，返回值只剩三元那一项 ⇒
`capOf(coral)=0 / capOf(stone)=0`（`capOf(kelp)=200` 走另一条 return，所以对）。
⇒ 珊瑚/石头/金属/精铁全存不进去 ⇒ bot 跑不穿整局 ⇒ `runHours` 恒 0，e2e 15 项全红。

**取证路径（下次照抄）**：`直接调 addRes` → 确认 state 同一个 → `capOf 各资源对比`
→ **`capOf.toString()` 打印全文** → 看见 return 那行的 `+` / `?:` 之争。
⚠️ 前四步全在推理，只有打印函数体才看见真相；`slice(0,300)` 会截掉 return。
⚠️ 断言为何假绿：石梁那条走 Infinity 路径没碰这条 return；「+200」那条比**差值**，两边一起错照样成立。
⇒ 补断言「每种材料的容量都拿得到 CAP_BASE」逐资源钉绝对值，e2e 335/335 → 336/336。
