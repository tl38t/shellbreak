## 22:4x 【用户报 bug】刷新之后市政树重置 —— **根因在 state.js，不是 civics.js**

**现象**：刷新页面后市政树节点全部回到未完成；**政体与政策卡却还在**。

**根因（state.js:188）**：`out.civics = fixTable(raw.civics, base.civics);`
- `fixTable(obj, ref)` 是 `for (key in ref)` —— 遍历的是 **ref** 不是 obj。
- 而 `base.civics = {}`（空表）⇒ 读回来是 **空对象** ⇒ 已完成的市政整张没了。
- 政体/政策卡是**标量**，走 migrateRun 里 `for (k in raw) if (k in base)` 直接拷贝，所以活下来。
- 那条注释还声称做过「老档补新 id」的加固 —— **它连老档里已有的 id 都丢了**，加固根本没生效。
- ⚠️ 不报错、不 NaN，症状只有「树重置了」，所以能一路活到用户手上。

**修法（state.js）**：别再用 fixTable 处理 civics。按**数据定义** `SB.CIVICS` 逐个 id 取：
- `SB.CIVICS.forEach(c => out.civics[c.id] = !!rawCivics[c.id])`；
- 值统一归一成**布尔**（`civics.research` 写的是 1、这里原本写 true，同档里两种值都能存在，`=== 1` / `=== true` 逐个比对就会一半错一半对）；
- 兜住「存档有、数据已删」的未知 id（照原样留，不静默丢）；
- `SB.CIVICS` 缺失时退回 `Object.assign({}, rawCivics)`。

## ⚠️ 工坊工具落点被用户纠正：斧 / 镐必须各管各的线

**用户原话**：「不是 斧子也是单独的采珊瑚加成，镐是单独的采矿/采石，也包括暖石加成」

### 我错在哪
第一版把斧和镐**都写 `target:'gather'`**，同挂在 `gatherMul` 上叠乘 ⇒
**买了斧头，石头也跟着涨**。用户明确否决。

正确语义（现在这版）：
| 工具 | 落点 | 效果 |
|---|---|---|
| 青铜镰 | `farm` | 采集者藻食 ×1.8 |
| 青铜斧 | `coral` | **只**珊瑚匠珊瑚 ×1.8（不碰石头/金属） |
| 青铜镐 | `stone` + `silt` + `warmstone` | 采石工石头、矿工金属 + **伴生暖石**，三行各 ×1.8（不碰珊瑚） |

⇒ **三件买齐不是「一条线 ×5.83」，是三条线各 ×1.8。** 这句要更新到任何描述里。

### 架构决定（记牢，别再退回）
`gatherMul` 恢复为**纯通用采集倍率**（礁石平台 / 深潜 / 洋流 perk / 科技），
`toolMul(s, target)` **从 gatherMul 里摘出来**，改为在**每个产出行上单独乘**：

```
coral     *= gatherMul * toolMul(s,'coral')
stone     *= gatherMul * toolMul(s,['stone','silt','warmstone'])
silt      *= gatherMul * toolMul(s,['stone','silt','warmstone'])
warmstone *= gatherMul * toolMul(s,['stone','silt','warmstone'])
farm      → farmMul * toolMul(s,'farm')
```
`tick` 与 `rates` **两处都要同式**（老纪律：面板撒谎家族的标准成因）。

### toolMul 的签名演化
`target` 现在是**数组**（一个工具可插多条产出行）。同组内两个工具才会互乘，
**不同组永不互乘** —— 这就是「各管各的线」的机制保证。

### ⚠️ 踩到的坑：`Array.isArray` 不能省
第一版写 `var want = (target && target.length !== undefined) ? target : [target];`
—— **字符串也有 length** ⇒ 单坑位（`'coral'`）被当成逐字比对，`t.target[0]='coral'` vs `want[0]='c'`
永远不相等 ⇒ **工具买了完全不生效，且不报错**。必须用 `Array.isArray(target)`。
