# 2026-10-04 · 删除「匠人」职业 + 连带清理

用户指令（附族民页截图「匠人 0 / 驱动加工、地热与祭坛」）：「根本没有这个职业，删掉」。

## 根因（为什么一个"没有设计"的职业会挂在 UI 上）

`config.JOBS` 里的 `craft`（匠人）是 2026-09-28 删「匠作」科技后的**幽灵行**：

1. `jobs.craft` 在全树**没有任何解锁口**（`eff.unlockJob:['craft']` 唯一的 craftT 已删）；
2. 但 `folk.jobUnlocked` 对「既无科技声明、也无市政声明」的职业走 `return !tid` = **true**
   ⇒ 匠人被当成「开局无条件解锁」⇒ `render.paneFolk` 的守卫
   `if ((s.jobs[j.id]||0) <= 0 && !jobUnlocked) continue` 判成 false ⇒ **恒渲染**，
   点 ＋ 还真雇得到人 —— 而雇了零产出（加工早改建筑自动；地热唯一产出口热泉井已删 ⇒ fuelRate 恒 0）。
   ⇒ 看得见、雇得动、什么都不产 = 用户说的「根本没有」。

## ⚠️ 顺带抓到两个**真 bug**（与删职业同源，玩家可见）

`tech.js:289` 与 `civics.js:1195` 把 **job 型条件的文案写死成「匠人」**，而现存 job 条件
全是别的职业 —— `techs.js:203`（scholar≥1）、`techs.js:459`（merchant≥5）、
`civics.js:229`（boost `merchant` 20）⇒ 它们一直把「学者/商人条件」印成「匠人」。已改读实际职业名。

## e2e 夹具修正（删职业直接触发的一条红）

`e2e.mjs` 的「迁移收回超编职业」夹具原本给老档塞了 `craft: 1`。删职业后 `migrateRun` 的
`fixTable` 按 ref 键遍历会**丢弃**该键 ⇒ 超编量 99→98 ⇒ `merchant` 只切到 `2`（期望 `1`）⇒ 红。
修法：把 craft 那 1 点转记到 `scholar`（保持 IDS 内 sum=133、超编仍 99、期望 `merchant===1` 不变），
**并新增一条断言**「已删职业（craft）的旧档键被迁移丢弃」。⇒ 老档带已删职业键这件事从此有回归覆盖。
