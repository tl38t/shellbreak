## 星球重构机 G.E.E.K 破壳后卡死（玩家反馈 → 修复）

**现象**（用户转述玩家）：「更新后破壳恢复了，但是星球改造器又卡着不动了」。线上 `V-20261103-2` = Ver1.0.14。

**根因（三层，全部实测坐实）**：

1. **主因** `src/shell.js:53` `if (s.broken) return 0;` 在 `tickShell` 首行，而 G.E.E.K 的推进写在同一函数 ③ 段
   ⇒ 破壳后进度永久冻结。早退发生在 `geekStarved` 置位**之前** ⇒ 面板仍显示「运转中」+ 倒计时冻住、
   无任何提示（这是玩家体感「卡着不动」的直接形态）。
2. **连带** `economy.hydroAlloc` 的 geek 判据只有 `geekOn && geekOwned`，没有「还有活干」
   ⇒ 不干活也照占 40/秒 热液能流（顺序在发射场之后、朱庇特之前 ⇒ 挤掉朱庇特/泰拉水舱）。
3. **老 bug（与破壳无关）** 「等 terraform 研究」「两阶段都完成」两态同样白占 40/秒，
   而 tickShell ③ 与 economy-rates 都判 `_geekActive` 不干活 ⇒ 流白烧、面板还显示在烧。

**死锁链（比卡住更严重）**：`terraDone` 永假 ⇒ `geekTerra` 永假 ⇒《严冬计划》（techs.js 的 cond 是硬门槛）
永不揭示 ⇒ 重核聚变 → 超临界致密材料 → 流浪泰拉科技全断 ⇒ 行星发动机永不解锁
⇒ 流浪泰拉挑战（goal = 50 座行星发动机 + 星核炉芯池 50M）**永久无法通关**。
破壳后玩家无自救手段：点「停机/启动」无效（早退在判开关之前），只能轮回。

**为什么 1.0.12 看不出**：那时破壳 = 全局停摆，什么都停。1.0.14 把其它 9 处门拆了才暴露。
`git log -S` 追到基线（2026-09-25）就有这行 —— 不是回归，是上一轮修破壳停摆时漏掉的连带。

- `src/shell.js`：抽出 `geekActive(s)` 作为「还有活要干」的**唯一判据**；把 G.E.E.K 从 `tickShell` 的
  ③ 段拆成独立 `tickGeek(s, dt, emit)`，**在 broken 门之前**调用。破壳后 ① 削壳 / ② 天穹钻机照旧停。
  顺带：无活干时清 `geekStarved`（否则改造做完后徽标永远挂着「缺×× · 停摆」）。
  导出 `SB.shell.geekActive` / `tickGeek`。

  早退判据与 `if (geekOn && geekOwned && _geekActive)` 三处一起改。
- `src/economy-rates.js`：改调 `SB.shell.geekActive(s)`（原本自己写了一份，三处副本已漂移过）。
- `index.html`：`?v` economy 205→206 / economy-rates 31→32 / shell 112→113。

## 顺带：一次 `TypeError: Math.max is not a function`（环境假象，不是代码 bug）

回归里出现过一次 `at activeTerraVat (src/economy.js:1714)  Math.max is not a function`，
整局模拟第一帧就抛。**但同一份代码在下一轮完整跑通了整局模拟。**

诊断方式：在整局模拟循环前后打印 `typeof Math.max` + `Object.getOwnPropertyNames(Math)`，
两次都是 `function`、属性齐全（abs…SQRT2 一个不少）。

结论：与那个 0xC0000005 同源 —— **进程内可见的内置对象属性被外部注入改写**。
⚠️ 判据：遇到「原生内置对象的方法莫名变成 undefined / 非函数」，先怀疑环境（360 主动防御
的 SafeWrapper.dll），**不要去改代码**：`Math.max` 这类内置属性不可写，代码层根本改不动它，
能改的只有进程外的东西。这类报错不能当回归结论。

## 破壳不再清挑战（goal 型 active 判据，用户拍方案 A）

**现象**：用户「存档留在破壳前，挑战还在；一破壳就会清除挑战，然后正常运行」。

**根因**：`challenges.active()` 的 goal 分支 `return s.broken && !d.persistAfterShell ? null : a;`。
`drift_terra` / `waterpollution` 没标 `persistAfterShell` ⇒ 破壳瞬间返回 null。连锁三个后果：
① 挑战页整排退回「尚未完成 / 下一档可挑战」；② `canStart` 只拦 `active`，于是变 true；
③ 卡片出现**可点的**「结算并挑战」，`begin()` 会直接 `startRun` ⇒ 当前 ERA10 进度当场丢掉。
真源从没丢：`s.challenge` 在、`evaluate()` 照常按 goal 发奖、寒流必冰封与太阳帆 ×0.5 是
`economy.js` 里硬编码 id 判断、根本不看 `active` ⇒ **坏的是状态与入口，不是挑战本身**。

**误推来源**：旧注释写「破壳后要造 50 台发动机，人口与产出不能还压着」——但 drift/waterpollution
根本不设走 `active()` 的人口/产出限制（`populationLimit` 只认 small、`productionMul` 只认 abyss、
`jobLimit` 只认 science），该理由对这两个挑战不成立。

**修法（A）**：goal 型只要未 `challengeDone` 就返回 a，破壳不是终点；删掉 4 处已冗余的
`persistAfterShell: true`；删 `render-pane-challenges.js` 的「壳外推进」只读块（修后无可达路径）。
`?v`：challenges 19→20、render-pane-challenges 20→21。

**验证**：`sim/probe_drift_shellgate.mjs` 16/16（含 waterpollution 同源、四项终局、通关后可再战）、
`sim/probe_drift_pane.mjs` 7/7（破壳后仍「进行中」、无重开按钮、无只读块）；
`--challenge-only` 79/79；全量 **1517/1559**，失败清单与基线逐条一致（唯一差异 = 海潮方碑数值漂移）。

**顺带修的过时断言**：三条「挑战总数写死 7」的断言（7→11）。四条终局挑战
（anarchy/good_old_days/three_launch_sites/eternity_moment）是工作区里**并行推进**的工作，
本轮读到过一次旧实现、09:54 又被换成 `dysonLaunchSites` + `unlockAdoptedGovPassiveCards` 版本
（非本会话所改，改动共存无冲突）。⚠️ 若同时开着另一个会话改同一工作区，注意串行。

## 本地礼包码通道（用户要求「加一个码给客户发 50 星屑」）

**做法**：不动平台链路，在 `CFG.REDEEM.LOCAL_GRANTS` 加一张本地码表。
`redeem()` 在 `alreadyRedeemed` 之后、`fetch` 检查**之前**先查本地 → 命中直接入账，**零网络请求**；
未命中才落回原 TDS 平台路径。理由：平台路径要先在后台建活动拿 ACTIVITY_ID，临时发一笔等不起。

**这条码是**：明文 `SHELLSTAR50`，config 里**只存哈希** `fe97c807f70f509ea85b8f3b3a340535951baede`
（= `sha1('sb:' + 大写码)`）。包是明文 JS，写 `code` 等于把码印发给所有会解包的人。
换码工具 `tmp/_mkcode.mjs`（直接加载真实 `redeem.js` 取 `localHash`，不另写一份算法 —— 两份一飘就永远对不上）。

**关键判据（易错）**：
- ⚠️ 发星屑**只加 `m.stardust`，绝不写 `m.stardustEarned`**。后者同时是三处口径：
  排行榜「最多星屑」（game.js `entries key:'star'`）、商店「累计结算获得」、
  `freshRun` seed 进 `s.got.stardust` 喂超古代科技/市政尤里卡 ⇒ 白送的星屑写进去 = 用福利换成就。
- ⚠️ 顺手置 `m.stardustShopUnlocked = true`：商店门是「首座轨道卫星」，有余额却进不去是死路。
- ⚠️ `ready()` 必须 = `platformReady() || localGrants().length > 0`。只判平台 ⇒ 只配本地码时入口整块消失。
- ⚠️ 本地码检查要放在 `typeof fetch` 检查**之前**（本地码正是绕开网络的那条路）。
- `e2e` 原「未配置时 ready() 为假」那条已改：清平台两项的同时**必须也清 `LOCAL_GRANTS`**，否则假红。

**验证**：`node sim/probe_redeem_local.mjs` 26/26；`--redeem-only`（本轮新加的单套件入口）66/66；
真实 index.html 里 iframe 端到端：`stardust 0 → 50`、`earned` 保持 `0`、商店解锁、二次领取被拒且余额不再涨。
全量三遍：**1531/1573、1530/1573、1531/1573**，失败清单与基线 42 条一致（第二遍多一条 `claim 无活动事件` = 已知旧 flaky）。

**线上事实**：1.0.14 包里 `CLIENT_ID`/`ACTIVITY_ID`/`redeem.js`/设置入口 DOM **全都在**
（解包 rc41 核对过）⇒ 客户现在就能看到「兑换码」入口，但**本地码要等 1.0.15** 才认。
