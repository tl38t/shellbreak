## 玩家截图诊断：「离线结算了但恢复的档不对」

**结论：离线补算没算错，是那份档本身就只有 108 秒。** 用截图数字反推整条链：

| 项 | 数值 | 推导 |
|---|---|---|
| 恢复提示 | 0.03 小时 / 壳厚 499988 | t=108s，已削 12 |
| 现在 | 存续 0.43 小时 / 已削壳 162 / 壳厚还剩 499838 | 500000−499838=162 ✓ |
| 离线 | 23 分 8 秒 = 1388s | 0.03h + 0.386h ≈ 0.43h ✓ |
| 离线削壳 | 162 − 12 = 150 | 1388s × 0.108/s ✓ |

⇒ 时间、壳厚、削壳量三者互相闭合，**离线区间确实被补进去了**。
⇒ 真正现象是「恢复的档 = 一份 108 秒龄的新档」：巢穴 0 级、资源 0、人口 0，符合 «108 秒还没攒够 5 珊瑚» 的开局态。
⇒ 也就是说：**存档在更早就已经不是原来那份了**，离线结算只是把它继续跑下去。

⚠️ 定位纠错：我一开始把底栏读成「已刷壳 162」，与 `render.js:1085` 的 `baseShell-shell=12` 矛盾，
按纪律裁切放大（`tmp/_crop_lower.png`）后确认原文是 **「已削壳 162」**，矛盾消失。**小字必须裁切放大再读**，这条又验一次。

**「档变成新档」的可能路径**（按可能性排序，需玩家侧信息才能定死）：
1. `RUN_KEY` 被清 —— 玩家点了主界面那个红色「清空存档」（`index.html:203`，`btn danger`，**就裸露在底栏**，靠二次确认勾选兜底）；
2. 容器/浏览器清了 localStorage（清缓存、隐私模式、换设备、平台更新容器重建）；
3. 存档损坏 → 这条**有保护**：`loadRun` catch 会 `preserveRawSave` 并把 problem 挂上，boot 直接 return 不建新档。
   只有「键根本不存在」才走 `startRun()`（合理，但也意味着**静默**开新档，没有一句提示）。

⇒ 无论哪条，**云端没档就救不回来** —— 直接印证「云存档纯手动」这个缺口就是要补的。
