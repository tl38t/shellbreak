### 关键设计判据（写进了代码注释）

- **「满」= 任一原料达到 capOf**（无上限原料不参与判定；全部无上限 ⇒ 退化「够一份就造」，
  否则那种槽永远不动）。
- **档位 = 当时可造量的百分比**，不是「造到 X% 仓位」（后者满仓时恒 0，槽死）。
  `Math.max(1, floor(all*pct))`：只防边缘「可造 1 份 × 25% = floor(0.25)=0 ⇒ 槽永不动」。
- **同一配方只占一槽**（占两槽 = 阈值判两次、只造一半的假象）；pct 只认 PCTS 档位（手改档拒绝）。
- **执行走同一个 `craft()`**（含 craftBlocked 门 / 成本夹取 / craftMul / addRes 台账），不另写结算。
- **emit=null**：2 秒一条「造出 N 石梁」会刷爆日志；markDirty 让面板数字自己说话。
- **UI 用按钮组不用下拉**：pane 每 2s 整块重画，select 展开态会被 innerHTML 冲掉。
- **未解锁不画控件**（cap≤0 整块不出现），不预告拿不到的功能。

## 修：热液能尤里卡读错口径（用户报「只显示减去的，应该显示总生产」）

根因：`industrialize`（工业化，era5）的尤里卡写 `cond:{t:'rate', r:'hydro', n:10}`，
而 flow 模型下 `rates().hydro` = **净消耗取负**（工坊吃 + 钻机吃，恒 ≤ 0）⇒ 条件**恒不成立**
⇒ 工业化永不揭示、热锻工厂永不可达；表面症状只有一句「尤里卡那行显示的是被吃掉的那截」。

### 落点（4 文件）

| 文件 | 改动 |
|---|---|
| `src/economy.js` | `steelRate` 增返 `hydroSupply: HF.supplyRate`（总生产）；`rates()` 增 `hydroSupply` 键（并把 `steelRate(s)` 提到 return 外算一次，别连调三遍 hydroAlloc）；`hydroAlloc` **提前返回补齐三个 Rate 键** |
| `src/techs.js` | `industrialize.cond.r` 改 `hydroSupply` |
| `src/tech.js` | 新增 `rateName(id)`（`hydroSupply` → '热液能总产出'，其余 = resName + ' 产出'）；`condShort` / `condText` 的 rate 分支改用它 |
| `sim/e2e.mjs` | 5 条新断言 |

### 关键判据

- **总生产与净消耗是两个口径，不许在 rates 里合并**：顶栏速率行要「这行每秒怎么变」⇒ 读 `hydro`；
  尤里卡「产出达到 N/s」要「汽轮机造出来多少」⇒ 读 `hydroSupply`。谁读哪个由读的人决定。
- **`hydroSupply` 不能进 `SB.RESS`**：`renderRes` 按 `for (var k in RESS)` 遍历 ⇒ 加了就多一行假资源。
  所以显示名走 `rateName()` 例外表，而不是塞进资源表。
- **提前返回必须补齐全部键**（含 `supplyRate/shopRate/skyRate`）：少一个键 ⇒ 读的人拿到 `undefined`
  而不是 0。`steelFlow` 的 `s.res.hydro = HF.supplyRate` 就是这样：解了 metalrefine 但一台汽轮机都没建时，
  顶栏热液能主数写成 `undefined`（**潜伏 bug，本轮顺手堵掉**，已加断言钉住）。

### ⛔ ② 真 bug：改配置对老存档完全无效（e2e 测不出，**缺迁移**）

**现象**：`CFG.ICE_SHELL` 已 500000，但浏览器里`game.run()` 读出来仍是 `iceShell=100000`、
上屏「25000 / 100000（25.0%）」—— 看着像改动没生效。

**根因**：`game.resumeRun(saved)` **无条件拿存档当本局**，而 `migrateRun` 对 `iceShell`
只做「是不是数字」的校验、**不重算** ⇒ 任何改配置前建的存档永远跑旧厚度。
⚠️ **`nums` 循环那段注释没覆盖这件事**，所以别以为「有 migrate 就够了」。

**修法（`state.js:migrateRun` 末尾，插在 `nums` 循环之后）**：
用**存档里的 `baseShell` 当版本戳**——它不随破壳进度变化，与 `CFG.ICE_SHELL` 不等即另一版本：
```js
if (out.baseShell > 0 && out.baseShell !== curBase) {
  keepRatio = out.shell / out.iceShell;         // 等比，不是直接赋值
  out.iceShell = round(curBase * 0.9^(perk.thin||0));
  out.shell = round(out.iceShell * keepRatio);  // 进度不丢
  out.baseShell = curBase;
}
```
**为什么等比而不是直接赋**：直接赋会把已凿到 25% 的进度重置成满壳 = 白送进度。
**为什么幂等**：`baseShell` 被同步改写 ⇒ 反复迁移不会把壳越翻越厚。
`perk.thin` 已体现在存档 iceShell 里，按比例缩放天然继承，**不重复乘**。
⚠️ 位置纪律：`out.perk` 在 514 行收口，本迁移在 611 行 ⇒ 顺序对，thin 才读得到。
